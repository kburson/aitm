## Summary

The plan matches the story's refined acceptance and its four legs are well bounded. It reuses the #457 route, keeps private material private, and allows a negative result. Several decision points are underspecified, so an executor could not tell a pass from a failure or an abort. Two of them concern an irreversible write to protected `planning`. I reviewed the plan and story only. I did not inspect the CLI or the #457 qualification.

## Findings

1. **No contingency if the pending state is not achieved (Step 1, Acceptance row 1).** The leg requires at least one terminal callback with capture status 3 and a missing receipt before switching. Nothing says what happens if native retention or an auto-settle clears it first, or if no callback is pending. Silently re-running would make the delayed-settlement leg unfalsifiable, so state the retry budget and the failure verdict.
2. **Ambiguous "retained" and "before native retention" (Step 1 vs. Acceptance row 1).** Step 1 requires a "retained terminal callback" with a missing receipt. The acceptance row requires one "pending before native retention". These read as opposite conditions. Define one term, for example "terminal callback recorded, receipt absent, native rollout still available for retry", and use it in both places.
3. **The live publication to `origin/planning` has no authority or rollback statement (Step 3).** The receipts are published to a protected remote and cannot be cleanly withdrawn. The plan says to record the writer identity but does not say who authorizes the live write. It also does not say what happens if only one of the two paths lands, or if the first publish returns a commit but readback fails. Add a pre-write authority check, an abort condition, and a partial-write disposition.
4. **Refusal-leg wording conflicts with the method (Step 3 vs. Acceptance row 3).** Acceptance says "Authorized writer refuses a mismatched origin". Step 3 uses a "no-network, unauthorized-origin checkout". The story asks for an unavailable or ambiguous result through the existing authorized writer and readback. Say whether the refusal comes from the shipped writer's origin/authority check or from the network failure. Also say which of the two this evidence represents, so the verdict is not overstated.
5. **The missing-binding control may pass on tests alone (Step 4).** "Reproduce through the CLI whenever possible" lets the leg pass on a focused test with no CLI evidence. Say how the missing owner-start binding is created in the scratch database. Say what counts as a pass when only the test is available, and require that fallback to be recorded as a reduced verdict.
6. **No outcome is defined for a wheel or hook mismatch (Scope).** The plan says to verify the hook config, wrapper, loaded wheel bytes and installed wheel source against #457. It does not say what to do on a mismatch. Say whether that stops the spike or proceeds with a recorded caveat.
7. **Unsupported conclusion in the closing sentence.** "The smallest viable workflow will distinguish the command task... from full coverage of that follow-up turn's own post-completion usage" states a finding before any evidence exists. Rephrase it as a question the evidence must answer.

## Required changes

1. Fix finding 1: add the retry budget and the failure verdict for the missing pending state.
2. Fix finding 2: use one defined term for the pending/retained state in Step 1 and Acceptance row 1.
3. Fix finding 3: add the live-write authority check, abort rules and partial-write disposition.
4. Fix finding 4: make the refusal-leg acceptance wording and the stated method agree, and say what the leg proves.
5. Fix finding 5: define how the missing-binding control is created, and the reduced-verdict rule for test-only evidence.
6. Fix finding 6: state the stop-or-caveat rule for a #457 environment mismatch.
