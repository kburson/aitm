## Cross-boundary behavior

- **Exit and entry selection.** The ordinary move checks both sides. An
  authorized Ready for Plan shelve evaluates destination entry while leaving the
  source exit guards out of that operation. This avoids using Plan admission to
  decide whether parking is allowed. The shelve test also checks ordinary
  transitions still select both sides. [Phase selection][legacy-source-6] ·
  [Shelve test][legacy-source-7].
- **Discussion and hierarchy.** The Backlog discussion hold is body-based and
  independent of parent readiness. A null parent Status passes the two narrow
  eligibility adapters. The general child-admission adapter refuses an unknown
  Status when a parent is present. The action-decision evaluator invokes the
  same guard registry during baseline and enriched evaluation. Keep these
  outcomes distinguishable when deciding whether to migrate a hold or add a
  parent policy. [Discussion test][legacy-source-8] · [Shared parent
  admission][legacy-source-9] · [Action-decision evaluation][legacy-source-10].
- **Capacity and dependencies.** Solo pickup passes the WIP wrapper without a
  sibling budget. The ordinary fallback warns when a sibling is active. Explicit
  rank-wave evidence can refuse an issue separately, and dependency observation
  has its own refusal and projection outcome. The legacy fallback permits Plan →
  Develop after checking whether a rank-wave policy applies. Decide the capacity
  pool, whether a pickup cap is needed, and any late dependency rule at the
  precise boundary. [Capacity decision][legacy-source-11] · [Rank-wave evidence
  tests][legacy-source-12] · [Dependency refusal tests][legacy-source-13].
- **Effect-bearing adapters.** Dependency reconciliation can update a
  disposition projection and has a separate provider failure path. Plan
  ownership evaluation can return a claim intent. Its commitment path re-reads
  the authenticated actor, exact Plan state and assignment, then checks
  exclusive ownership after the authorized mutation. Keep those provider effects
  separate from the typed predicate and report a failed projection or commitment
  explicitly. [Dependency adapter][legacy-source-14] · [Ownership
  commitment][legacy-source-15].
- **Planning and closure body rules.** The shared body check covers Deep-Dive
  Analysis placement, marker-gated content minimums, checked Dependency Map
  evidence and checked Verification Commands. Test entry omits the last rule.
  Done adds pre-close completeness and required lifecycle labels, with a warning
  path when the project makes the labels advisory. On an epic, a Closed Not
  Planned child triggers a separate outstanding-criteria check. The criteria
  need delivered proof or an explicit scope disposition. [Body
  rules][legacy-source-16] · [Child disposition
  implementation][legacy-source-17].

## Open policy choices

- **Discussion hold.** Use an attributable hold and clearance record where the
  project needs discussion to block admission. The policy owner and C110 should
  decide which legacy markers qualify and who can clear them. Preserve an
  unresolved migration as uncertainty.
- **Fields, placeholders and inheritance.** Require current structured story,
  acceptance and refinement evidence. A project may add formatting or board
  projection requirements. Resolve the independent parent admission floor from
  scoped parent provenance and actual prerequisites, with the accepted
  integration-resource route available. C110 carries choices to #12, #37 and
  C46.
- **Capacity and pickup.** Define the planning capacity pool and any separate
  pickup cap explicitly. Keep ranked wave readiness and dependency satisfaction
  as distinct rules. Use the named owner and actual gate in the C110 decision
  fixture.
- **Deep dive, approval and ownership.** Preserve accepted scope and current
  plan/JIT evidence. Decide whether the old deep-dive marker adds an assurance
  obligation and whether issue assignment has a business purpose beyond scoped
  actor and binding authority. C108 and C109 contribute their evidence before
  C110 records the decision.
- **Late blockers and code complete.** Decide independently where dependency
  rechecks belong after Plan. Protect attested source approval and verified
  delivery on their exact candidate and target. Record a typed handoff only if
  the old code-complete marker has a separate required meaning. C108 and C110
  carry the resulting decision to the verification and closure owners.
