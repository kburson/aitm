## Unit-test pilot

The target is 90% isolated unit tests and at most 10% integration tests, counting local and systems integration together. Count unique collected node IDs per supported host. Keep the product PR inventory visible as a separate cohort. Adding unit cases alongside an equivalent integration matrix is useful for the pilot and does not count as migrating that matrix.

1. Exercise scope handoff ordering directly through the in-memory timeline. Cover a later handoff on its own and the same handoff when an earlier transition invalidates its expected generation.
2. Exercise the journal's accepted-child rule with a stubbed database query and real decoded journal values. Cover a single qualifying child, equal usage, and ambiguous competing children.
3. Compare the covered elapsed and test phase time of the two isolated cases with the existing representative integration tests. On a disposable source copy, inject a handoff-ordering fault and an equal-usage fault. Confirm that both test boundaries detect their respective faults.
4. Preserve the integration witnesses for native receipt wiring, filesystem identity and SQLite persistence. Use the pilot results to identify which policy cases can move in follow-up, and retain the 30-second budget for a coverage-enabled 1,000-unit-test cohort.

### Pilot results

Three alternating samples on the same macOS arm64 host used Python 3.13.9, the repository coverage configuration (branch and subprocess measurement), and one pytest process per cohort. Wall time includes interpreter and pytest startup, collection, test phases, and writing coverage data. It excludes the subsequent combine and JSON export.

| Representative behavior | Isolated median test duration | Integration median test duration |
| --- | ---: | ---: |
| An earlier handoff holds a later handoff with a stale generation | 0.001 s | 0.437 s |
| Equal usage cannot create a journal content dispute | 0.003 s | 5.613 s |
| Covered process wall time for both cases, including overhead | 0.397 s | 6.547 s |

The two isolated cases exercise the same policy assertions about 16.5 times faster in this sample. Reversing handoff order or disabling equal-usage rejection each made both the corresponding unit test and the integration witness fail with an assertion. The changes were applied to temporary source copies. All original cases passed with the intact source. The integration cohort reached additional scope and journal branches, including native proof wiring and persistence. These tests should stay until each contract has a focused retained witness.

The separate serial coverage-enabled fast-unit run passed **548 collected IDs in 3.76 seconds** on this host, including four Python and pytest startups across product, CI tools, board and dashboard. Dashboard JUnit includes 20 nested subtests. The denominator comes from the exact collected IDs and passing parent call reports. The current inventory cannot directly test the 1,000-unit target. This observation excludes environment provisioning and coverage export and does not establish hosted timing.

This pilot adds four fast-unit cases and removes no integration witnesses. Relative to the 1,525-case PR baseline, this brings the classified product PR share to 110 of 1,529 cases (7.2% unit). At that fixed inventory size, reaching 90% requires 1,377 unit IDs. Move policy matrices in the journal and scope families first, followed by installation decisions and CLI validation. Record the policy assertion moved, the nonredundant integration contract retained, and the before/after counts and timing. Verify the migrated policy and adapter scopes in #423.
