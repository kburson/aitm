## Collect the baseline

1. Pin the exact tested tree, Python and uv versions, runner OS/architecture, pytest arguments, coverage configuration and child instrumentation. Record warm/cold state. Inventory every test lane from the workflow definitions, including base and candidate product, helpers, mapped checks, installed-wheel smoke, separately triggered advisory runs and the category sweep. Record the actual coverage mode or a reason the lane could not be measured.
2. Run the covered product inventory twice on equivalent Linux runners, first with one worker and then with the configured three-worker work-stealing setup. Use the same observer and coverage setup for both arms. Run the helper coverage inventory with phase telemetry. Compare category sharding with the sweep's serial reference at the same tree and host. Run a separate coverage-enabled pair if the production-shaped sweep runs without coverage.
3. Capture pytest report node ID, phase, start/stop, duration, outcome and worker; capture a run and attempt ID, setup/collection times, child receipts, test exit status, coverage combine/export time and artifact sealing time. Keep runner jobs and worker intervals separate. Mark collection failures, skipped phases and unobserved intervals explicitly. Export raw receipts and per-test CSV.
4. Reconcile collected node IDs, complete phase outcomes, and line and branch coverage by file before comparing performance. Calculate serial wall time divided by sharded wall time, maximum shard duration divided by mean shard duration, aggregate worker seconds and peak simultaneous active workers using report intervals. Record gaps and host jitter. Attach the evidence to #422 and give #423 the pinned baseline and raw artifact links.
