## Capture contract and ownership

- **Timing from Core.** Capture story or bound draft, actor pseudonym, role, phase, attempt, stable source identity, occurrence and recording times, and qualified start and end boundaries. Qualify native turn start and finish, in-turn tool spans, scope switches, review handoffs, owner request and response, and workflow kickoff and verified delivery. Store evidence with coverage and an opaque provenance reference. Keep raw agent transcripts, paths, prompts and provider identifiers in the source system. Preserve unsupported, missing, late and conflicted evidence as explicit gaps. During the bridge, use the existing manual recorder, digest-bound receipt and atomic planning registration for one active story. [Capture checklist](https://github.com/kburson/aitm/blob/8a17077c3dbabcce3e4682c42d8cd856d5d99f3d/tools/story_dashboard/capture.md) · [Operator workflow](https://github.com/kburson/aitm/blob/8a17077c3dbabcce3e4682c42d8cd856d5d99f3d/tools/story_dashboard/operator.md)
- **Cost from Usage Monitor.** Consume one qualified immutable report scoped to the exact project, story, attempt, window and cutoff, with publication identity, rate digest and pricing basis. Reconcile priced and unpriced usage. Label an API-equivalent estimate as such. Tool duration adds no charge on its own. An unselected report, a selected report with no story attribution and an attributed record with no verified price are distinct gaps. [#230](https://github.com/kburson/aitm/issues/230)
- **Replay and aggregation.** Key evidence by stable scope and source identity. Identical replay is a no-op. Corrections retain the old receipt and supersede it explicitly. Hold conflicting or incomplete publications and retry from the last verified point. Use qualified milliseconds, count a same-actor overlap and a tool within a turn once, sum distinct actors' engagement, and count simultaneous work once in working wall time. Roll up unique descendant effort plus direct epic effort. Keep owner wait, idle and unattended execution outside Actual. Calendar elapsed requires its own evidenced boundaries. ## Publication and presentation

Keep numeric value, coverage, reason and evidence-through time independent for each metric. Render an observed subtotal as “3.0619 h recorded · Partial.” Render missing inputs as “No work receipt,” “Response boundary missing,” or “Usage report not selected” as applicable. Keep the current Unknown classification for an unknown numeric value and expose the reason on the main row. Use zero only when evidence establishes zero for the entire declared scope. Keep unresolved waits and stale evidence visible. Evidence-through is the latest verified source checkpoint for the metric and scope. Complete requires coverage for the entire declared window, including any relevant source disconnects or gaps. Keep stale publication separate from a metric whose evidence is missing or old. Use the C44 outcome and exact estimate revision for calibration, with matching phase, role and agent scope, attempt and timing basis. Exclude Partial or Unknown.

The publisher builds a versioned, read-only view from a pinned planning SHA and UTC cutoff. Record the builder SHA, independent timing and usage evidence-through times, snapshot digest, and publication time. A new build time and a new evidence cutoff are separate facts. Use an allowlist for the hosted payload. Start with public issue number, title, lifecycle state, approved aggregate values and reason codes, publication provenance, and links to the public issue. Include no actor-level contributions, raw receipt references, detailed private source data, credentials or unapproved usage fields in HTML, embedded JSON, artifacts or logs. Rollup drilldowns can show direct and descendant totals from the allowlisted view.

For the preview bundle, use a manually triggered build with explicit planning SHA, cutoff and visibility profile. The first slice exits when the validated bundle is downloadable and reproducibly serves locally. In the next checkpoint, qualify a separately authorized host with a synthetic bundle and verify that the browser reads back the expected digest and pin before publishing real metrics. Move to a recurring refresh after measuring build latency and agreeing on a freshness target. Publish a new snapshot only after validation and serialization against the last successful publication. A failed build or out-of-order completion keeps the last valid version and shows stale status when its freshness window expires. An intentional historical replay uses a separate preview target. Start with GitHub Pages for an explicitly approved public payload. For restricted metrics, use an authenticated host such as Cloudflare Access and test anonymous access to HTML, JSON, production, preview and alternate origins. This public user-owned repository currently has Pages disabled.
