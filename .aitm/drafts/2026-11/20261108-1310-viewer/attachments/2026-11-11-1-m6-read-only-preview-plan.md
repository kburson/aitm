# #1 M6 read-only preview implementation plan

> **For agentic workers:** Use the normal reviewed story pickup and source delivery workflow when implementing these steps. Retain the planning pin and source review for each leaf.

**Goal:** Produce a downloadable, offline-capable read-only preview whose metrics show a value or a coverage reason, an evidence-through time and a last verification time.

**Architecture:** Reuse the existing pinned story dashboard reader and fold. Project its values into a separately versioned allowlisted preview bundle and render that bundle in static HTML. The preview is independently useful before the production Core and GitHub contracts land.

**Tech stack:** Python 3.13+, Git, standard-library JSON and static HTML, CSS and JavaScript.

**Design:** [Coverage and preview](2026-11-11-1-hosted-dashboard-coverage-design.md) · [Refinement](2026-11-11-1-m6-read-only-preview-refinement.md).

## Constraints and review focus

- #100 and #133 must complete before any child of Core Epic #2 is picked up. The preview uses shipped tools and pinned planning data. Leave production M6, M2, Cost publication and hosting gates with their existing owners.
- Preserve the current `make dashboard` path and published snapshot contract. Keep Complete/Partial/Unknown values independent of reason, evidence-through and verification. Preserve a verified zero. Keep age, elapsed, Actual, working wall time, owner wait and Cost distinct.
- Build timestamps cannot become evidence timestamps. An unverified or unmatched receipt yields no last verified time. Missing historical evidence cannot be filled from progress timestamps or from later observations. For Cost, distinguish an unselected report, lack of story attribution and incomplete price.
- Hosted-safe output is a structural allowlist. Preserve the previous artifact on failure. The first deliverable ends at a reproducible downloadable/local bundle. Implementation pickup would be a separate bootstrap authorization under #1 M6. The master plan still sequences formal M6 implementation after M1. Hosting and refresh scheduling are later checkpoints.

The envelope watermarks are the maxima of admitted evidence-through UTC for the displayed timing and usage metrics respectively, or null when there are none. They do not imply complete coverage or an operator verification. Keep source and build timestamps explicit and inject the build time for deterministic replay.
- [ ] Emit only approved story ID, title, state, ancestry summary, fixed public issue URL, and metric value, unit, coverage, reason codes, evidence-through UTC and last verified UTC. Omit excluded rows and references to their IDs, and withhold inclusive values that include excluded descendants, with a controlled Scope excluded reason. For synthetic previews use the supplied fixtures. Public real-data publication is outside the first slice. Apply the structural and value allowlists to HTML, JSON, the manifest and diagnostics. - [ ] For each metric, map known reader reasons to controlled public codes. ## Leaf B. Render and qualify a downloadable bundle

**Estimate:** 3.0 implementation agent-hours. **Depends on:** A. **Files:** `tools/story_dashboard/preview.py`, `tools/story_dashboard/preview.html`, `tools/story_dashboard/tests/test_preview.py`, `tools/story_dashboard/README.md`.

- [ ] Expose an explicit preview CLI with planning repository, exact planning SHA, data cutoff, builder SHA, build UTC, optional configured verification pin, a required local-review or synthetic visibility profile, and external output directory. Rebuild the snapshot and its validation together from the pin before projection. Emit validated preview JSON, a digest manifest and standalone HTML as one staged bundle. Reuse existing static rendering safety and atomic-write primitives where appropriate. Render only the allowlisted preview object. Publish a content-addressed bundle, then update a last-valid pointer atomically while holding the destination publisher lock. While holding it, reread the pointer and reject a non-descendant planning SHA, decreasing cutoff, or duplicate pin/cutoff with conflicting digest. Use separate output channels for different visibility, project and usage scope/rate basis profiles; compare publications only within a channel. The identity binds the data pin, cutoff, verification input and preview bytes with fixed build inputs. A replay of that identity is a no-op. A replacement at the same planning pin must have a later cutoff. A historical replay uses a separate directory and does not move the current pointer.
- [ ] Show a primary reason next to every Unknown metric on summary rows and all applicable reasons in details. Show “Last verified” with explicit UTC or “Not yet verified,” plus separate “Evidence through” and a page-level build time and planning pin. Show pending waits separately. Warn when the publication is older than an explicitly supplied preview freshness window. Keep values with Partial coverage labeled as recorded subtotals. Keep direct and descendant Actual and separate timing and Cost scopes inspectable.
- [ ] Document the explicit local command, approval boundary for real-data hosting, and how to verify the bundle digest against the manifest and compare the browser's planning pin with the manifest pin separately. Render locally in a clean checkout from the pinned #139 before/after and a synthetic fixture. Verify #139 gains one Partial Actual interval, no new Cost or wait is inferred, unknown reasons and verification nulls are visible, and a canary excluded story, title, hidden contribution and private source string are absent from HTML, JSON, the manifest and diagnostics. Verify failed, stale and competing publishers retain the appropriate last-valid artifact. Run `python3.13 -m unittest discover -s tools/story_dashboard/tests` and the normal source review and delivery gates.
