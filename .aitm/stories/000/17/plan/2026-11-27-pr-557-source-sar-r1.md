## Independent verdict

CHANGES_REQUIRED

The installed describe path does keep a completed local result when publication is still unresolved, and the disjoint fast-forward replay path retains the losing chain. The conflict and reconciliation contract is not met.

1. `packages/aitm-core/src/aitm_core/store/reconcile.py` — choosing the shared history reports the original operation as published. With `replacement is None`, `reconcile` still returns `LocalOutcome.COMPLETED` and `PublicationOutcome.VERIFIED` for that same `operation_id` after moving the local ref onto `expected_shared`. That records the unpublished operation as a verified shared result. Return a result that selects the verified prefix, keeps the recovery ref and the retained local evidence, and leaves the original operation unpublished.

2. `packages/aitm-core/src/aitm_core/store/reconcile.py` — a scoped resolution replaces `intent.payload` with a lineage document whose `original_payload` is the replacement’s own payload. The substantive request is not what `mutate` submits, and the lineage is not an additional supersession record. Keep the caller’s operation bytes intact, require a new operation id and the conflict’s write scope, and store supersession (`operation_id`, retained revision, original request identity) beside that operation.

3. `packages/aitm-core/src/aitm_core/store/publication.py` and `packages/aitm-core/src/aitm_core/cli/dispatch.py` — a completed local operation is dropped when publication fails. Both the `ReplayConflict` handler and the transport handler build `PublicationResult` without `local_completed`, so it stays false. `dispatch.publish` then reports `LocalOutcome.UNAVAILABLE`. Pass the flag through whenever the local receipt was found, including conflict and uncertain push failures.

4. `packages/aitm-core/src/aitm_core/store/publication.py` — `_replay` rejects every retained operation that has `pending_actions`, so an otherwise disjoint whole operation never replays. This path only rebuilds store commits through `evaluate_operation`, `_record`, and `create_commit`; it does not run the pending-action runner. Replay those operations under the current policy and the full read and write set, keep their action records on the new commit, and do not invoke external actions again. Keep the current refusal for operations that already carry guard results so a stale positive guard is not reapplied.

5. `packages/aitm-core/src/aitm_core/store/publication.py` — replay fences only `change.read_set`. A write or event path outside that set is still applied, which can replace remote prose, or `blobs[path]` raises `KeyError`, which `publish` reports as `PublicationStatus.PENDING`. Before building the replay commit, require every write and event path to be covered by the operation’s read/write preconditions against the candidate tip. An incompatible authored path, event stream, relationship, or policy input must be `PublicationStatus.CONFLICT` with the recovery ref kept. Deterministic damage to the retained request must not be classified as an uncertain push.
