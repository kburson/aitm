## U13 repair ownership

Extend U13's approved file list to include two narrow write-admission checks in `ledger.py` and the relationship-publication adaptations in the shared inbox path in `scopes.py`. U13 still owns its typed envelopes in `types.py`, CLI, relationship projection and tests. Preserve provider-scoped admission, private root and source proof behavior, existing unrelated batch and command paths, and the unreleased schema version. This scope does not transfer ownership of U08 anchor registration or U06 accounting.

1. Treat draft alias and parent effects as inbox-only records. Reject direct `Ledger.apply` of either type before durable writes, including same-project and foreign-project payloads. In `commit_command`, accept these effect types only for the matching typed command, project and command ID. After the exact-replay and expected-sequence checks, require every new final relationship disposition and its complete effect tuple, including keys and revisions, to match the static validator in U13-owned `relationships.py`. It depends on typed records and the fixed read-only view, with project reference derivation supplied internally by the bound ledger. It does not import `ledger.py`. Both the ledger and the dispatcher call the validator directly. Callers cannot inject a validator or select another path. The validator determines graph validity, alias and parent values, and the allowed canonical child normalization. Commit effects and the current disposition atomically.
2. Preserve publication order between relationship commands that wait in the inbox together. Allocate an order under the existing pinned, private inbox publication lock and persist it atomically with each queued relationship command. Use a closed transport shape and preserve canonical command bytes, digest and opaque ID independently of transport order. Take the same mutex for a consistent ordered drain snapshot, then release it before commits and acknowledgments. An exact pending replay retains its publication order. A retry after final acknowledgment uses the durable receipt. Process relationship commands strictly in publication order. Stop that drain at the first command that fails to reach a committed disposition and leave it and all later relationship commands queued. Halt the relationship drain with a sanitized diagnostic when a final publication has missing, malformed, duplicate or unclassifiable order. Continue independent valid non-relationship commands. A restart or partial drain preserves the relative order of all remaining commands, including committed items awaiting acknowledgment or retirement. A queue-local order can reset only after there are no outstanding relationship files. All non-relationship commands, including the later U08 anchor command, retain their existing shape without relationship order. U02 provider ordering and boundary attestation stay in force.
