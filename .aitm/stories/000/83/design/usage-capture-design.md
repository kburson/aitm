# Continuous agent usage capture

## Intent and sequence

AITM needs a measurement system for the life of the project. Install and qualify it before [Core #2](../../2/story.md) enters delivery work, starting with [C01 / #3](../../3/story.md). Early adoption sets the start date for the evidence. The same collector and ledger continue during and after Core delivery. Core later adds workflow-supplied bindings and usage ingestion while this producer continues to observe the providers.

Capture model usage for brainstorming, design, planning and document review, development, test, source review, delivery and housekeeping. Preserve task and feature rollups, API-equivalent dollars for Buy a Feature, and separate actual billing and provider subscription observations. The [#73 spike](../../73/attachments/report.md) establishes the supported evidence and limits. Viewer surfaces, automated billing reconciliation, delivery forecasts, and cloud or remote capture are separate work.

## Local collection and operation

Ship a standalone Python 3.13+ package `aitm-usage` in `packages/aitm-usage/` on trunk. It can be installed on the project Mac before any `aitm-core` package exists. Ship the CLI, the collector and a versioned export together. Use standard-library SQLite and a per-user macOS LaunchAgent. The service runs on login, scans every 15 seconds while awake, and catches up on retained records after restart. Keep the interpreter and application paths absolute in the plist. A versioned install or upgrade reuses the same project identity and ledger. Stop and uninstall leave the database and export available. Back up the database using SQLite's backup API so an active writer cannot leave a torn backup. Show installed version, heartbeat, source watermarks, observed-through times, lag and gaps in `status --json`.

The project registration has a stable project UUID, approved source roots and permitted checkout or worktree anchors. A reader may identify candidate sessions from local metadata. Eligibility applies to each observed segment. Allowlisted roots constrain every read. A recorded project checkout or an explicit project binding may enroll a session segment from those roots, including a reviewer launched outside a registered worktree. A later unrelated segment contributes no project observations. Persist the activation cut-off before scanning. For existing open sessions, baseline at the last provable pre-cutoff record and process eligible post-cutoff records even if the first scan is delayed. An in-flight span that cannot be separated stays Unknown. A revision of a pre-cutoff request stays with that request. Advance the accounting baseline across excluded segments without retaining their usage. Catch-up includes eligible later archives. Earlier backfill is separate. Store the database and private logs under a per-user directory outside Git with restricted permissions. Store provider request and session identifiers only as stable local keyed pseudonyms, with the key backed up alongside the database and kept out of exports. Never persist or export prompt text, reasoning content, tool arguments, credentials or account labels that identify the account owner. The service performs local reads and no model calls. Its health and coverage do not enforce workflow transitions.

## Work scopes

A scope binds project, stable draft or GitHub issue, work phase and participant to a provider session. A scope may also carry attempt, review ID and role. A monotonic per-session scope sequence and a verifiable request or turn boundary order changes. A marker created mid-request takes effect at the next identifiable boundary. It never retroactively reassigns earlier usage. In standalone operation the agent marks scope through a private durable inbox using a session reference and boundary observed by that adapter. The collector validates it against the enrolled source and acknowledges it idempotently. Emit the child marker during the preceding epic-scoped work or before the next turn begins. To switch back, emit a corresponding epic marker. A serialized, source-proven request boundary can switch scope within a turn. When only a turn boundary is provable, mark before beginning that next turn. Order by proven boundary and marker identity even if the scan saw the boundary first. Pending or unverifiable switches leave affected usage ambiguous until the source order is proven. Corrections retain the old as-of projection. Later launchers and workflow actions can submit the same records.

- **Before Develop** the shared planning chat and worktree can cover many items. Record epic hydration and cross-child planning once directly on the epic. Scope focused child refinement, planning or review to that child when a request boundary is known. If a request serves several children in a known epic batch, retain it as direct epic usage. Keep unknown attribution in a separate bucket that can be corrected by a recorded decision.
- **During Develop through delivery** bind the fresh story worktree, assigned owner and attempt to the story. A dedicated binding is a default for that owner only. A conflicting marker while that development binding is active creates an attribution conflict and leaves the affected observations unassigned pending a recorded correction. Record each independent reviewer separately and carry the same item and review ID across providers. Project-wide housekeeping has a project scope. Housekeeping tied to a story or epic carries that scope and phase, including work after delivery.
- **On graduation** retain the draft ID and add its permanent issue alias. Keep explicit parent links for rollup. Reject cycles and contradictory aliases. Sum an epic's direct usage and each unique descendant's direct usage exactly once. Scope corrections are append-only decisions with recorded evidence. Unknown items stay visible outside the attributed totals.

## Provider records and accounting

V1 supports the local Codex and Claude Code surfaces observed in #73. Checkpoint each source as one SQLite transaction with its observations. Keep a source incarnation, byte cursor and a validation anchor. A partial final line waits for completion. Handle a replaced file by resuming only with verified continuity or opening a separate source incarnation with an explicit coverage gap. Distinguish the physical file incarnation from the logical session stream. Live-to-archive moves or copies resume the same stream when recorded prefix and source anchors verify continuity. Quarantine an unverifiable overlap rather than opening a second additive stream. Conflicting duplicates go to diagnostics and leave the prior observation intact. Missing history remains Unknown.

- **Codex** reads session metadata, turn context and `token_count` rows, including supported archived rollouts. Use positive differences in cumulative token categories, checked against last-request usage when present. A known zero start can contribute its first delta. A truncated file establishes a baseline. Key a qualified observation by pseudonymous session, verified counter epoch and ordinal in the logical stream. Equal totals add no usage. A reset gets a distinct epoch only when provider source evidence establishes a new origin. Reused values alone are insufficient. Otherwise a regression or a difference that cannot be reconciled creates a coverage gap. Preserve known aggregate usage for an unallocated span without presenting it as fully priced request usage. Track model and effort with the boundary that supplied them.
- **Claude Code** reads allowlisted local project JSONL. Group usage by session and request identity, cross-checking message ID. Disagreement or missing identity leaves the affected evidence quarantined. Repeated streamed rows are cumulative revisions of one observation. Monotonic newer versions replace the current projection while history stays traceable. A transcript ending mid-request keeps that observation partial unless a session-matched terminal result or cumulative cost checkpoint reconciles the exact request prefix and proves completion. Retain observed partial quantities and coverage when no such proof exists. Distinct reviewer and author usage is counted independently. Provider rows without a verifiable session or identity create a gap. For nested agents, prefer independently identified request observations. If the evidence shows a parent total already contains a child, the aggregate is diagnostic alongside the details. If overlap cannot be resolved, keep one qualified aggregate outside attributed totals.
- **Token and API-equivalent cost** keep uncached and cached input, cache write classes, output and any reasoning subset with source units and availability. Reasoning included in output is counted once. Version the public rate table and retain model, processing tier, supported context thresholds and pricing basis. A model or rate category with insufficient evidence retains its measured tokens and an Unknown price. Effort is an analysis dimension. No flat token multiplier or elapsed-time cost proxy.
- **Account subscription and actual spend** are independent records. Keep provider, pseudonymous account, bucket, reset window, source, timestamp and observed precision for quota. Prefer inline observations and optional explicitly invoked read-only sampling. All account readings, including changes in an apparently isolated interval, remain account-window observations. Per-agent burn stays Unknown without a provider debit attributable to that request. No assumed monthly bucket. Actual spend requires attributable billing evidence. V1 retains an availability field and no billing connector.

## Durable handoff to Core

The collector ledger is the authority for captured provider observations, scope events and corrections. It is independent of Core's rebuildable index. The versioned JSONL export uses stable source keys, normalized quantities, scope, coverage and pricing provenance. Each export is an as-of projection at a transactionally fixed ledger sequence, with observation and scope revision references, the pricing version and explicit partial flags. Re-exporting the same cut-off and rate card produces the same records. The local ledger retains the revision history. Partial observations can be exported with their status and held back from a Core importer whose contract cannot represent them. A later adapter presents compatible records through [C44 / #51](../../51/story.md). It carries stable source identity, enforces idempotent import and tracks accepted export progress with durable per-key pending and reconciliation dispositions. A later revision must reconsider previously withheld keys even when an export watermark has moved forward. The collector keeps writing to the same database across that integration. Core owns accepted usage facts and downstream projections. It does not ingest raw provider transcripts.

Until the later adapter proves compatibility, preserve the export and the local history. If C44 accepts only immutable observations, import a final compatible observation once. Corrections to already imported observations require a supported additive correction or an explicit reconciliation queue. Never resend a different payload under an accepted source key. Ledger upgrades and rollback retain existing data and either run a versioned migration with backup and validation or refuse an unsupported schema. Before adopting a new collector or Core import path, reconcile overlap by stable identity and verify parity over a known export.

## Acceptance and readiness

- Observe a single planning chat hydrating at least two children, then scoping focused refinement and planning in the same checkout. Verify direct epic usage, each child's direct usage, graduation continuity, separate review participants and one inclusive rollup. Also exercise story ownership and related housekeeping in a dedicated development worktree on authorized work or a controlled fixture.
- Exercise first-scan delay, in-flight activation, eligible-to-excluded-to-eligible, and archived replay or copy. Verify Codex repeats, truncation, a real reset with reused values and conflicting keys. Verify Claude streamed revisions, identity conflict, partial terminal state and replay after restart. Exercise the actual scope marker in both arrival orders, including the first child request, return to the epic and a nonowner in the development checkout. A changing quota fixture still yields Unknown per-agent quota and actual spend.
- Qualify the export handoff with an immutable-receiver fixture that covers interrupted replay, a withheld request finalizing later, a correction after acceptance and a conflicting key. Live C44 adapter adoption follows its own qualification.
- Verify unattended startup on the project Mac, normal log collection while awake, catch-up after a service restart, private state permissions, and a recoverable backup and upgrade rehearsal. Compare sanitized exports before and after reprocessing and show no duplicate observations or private content. The export and diagnostics use a fixed field allowlist. Backup and restore verify project identity and pseudonym-key identity.
- Before Core C01 pickup, retain a dated activation receipt from real Codex and Claude Code work on the normal local routes. It names the installed collector version, live heartbeat, both source watermarks, scoped usage evidence and export verification. The receipt is a sequencing checkpoint for this project. Installation, activation and Core delivery follow later execution authority.
