## Implementation boundaries for the pickup review

- Use one exact clone-local journal identity derived from store UUID,
  repository and literal planning ref. Keep append order and enough prior
  and intended state to reconcile an interrupted local ref advance. Detect
  invalid or partial journal data before authorizing a new shared checkpoint.
  A missing journal alongside retained frontier refs is an integrity hold.
- Take the network observation outside the clone lock. Under the C06 guard,
  re-read the journal identity and local literal ref. If another supported
  refresh won while the fetch was in flight, discard that observation as
  stale and retry outside the guard. Only admit the pinned candidate,
  independently proven ancestry and exact validator outcome. Quarantine refs
  are internal and cannot serve as a writer base.
- For a fresh installation accept only the configured trusted genesis or
  separately supplied checkpoint. Report the pre-observation rollback limit.
  Once observed, rollback, sibling, confirmed deletion or unprovable ancestry
  fence shared publication. A content-invalid descendant still establishes
  a retained shared checkpoint. A subsequent verified repair must extend it
  and use the existing C06 verifier slot. The actual forward repair producer
  remains in C10.
- Use distinct exact configured code and planning remotes and namespaces.
  Validate the fetched code-default commit's independently anchored history
  before admitting its exact observation into the validated code view.
  Use the existing C07 resolver against that admitted observation. Unusable
  committed settings or changed routing fence mutations in both modes. The
  worktree copy and the candidate receipt cannot supply policy or an anchor.
  Leave C07's committed policy parsing and C90 parsing boundary in place.
- The existing planning CLI only has a validation route and a fenced repair
  stub. Supply the explicit refresh option on validation and a service
  preflight for mutation so future mutating commands use the same boundary.
  Test that the service refresh occurs before taking any operation guard.
  Keep the stale/unknown disposition and shared effects pending in the
  typed service result, and demonstrate it with the installed validation
  command bound to an independently supplied installation.
