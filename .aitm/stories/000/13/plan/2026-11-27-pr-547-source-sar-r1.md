## Independent verdict

CHANGES REQUIRED

The C08 continuity and admission core matches the approved hold rules, but the leaf does not meet two acceptance checks that are visible in the same diff: out-of-band worktree retention after the ref compare-and-swap, and one publication classifier shared by explicit refresh and mutation preflight.

### Blocking

1. Out-of-band worktree integrity is not established on the path `test_out_of_band_checkout_after_precheck_fences_and_preserves_worktree` exercises.

`packages/aitm-core/src/aitm_core/store/fetch.py` runs `gate(before, candidate)` and `gate.assert_excluded()` before `update-ref --stdin`. The test adds a worktree and writes an index only inside that `update-ref` call, then requires all of the following: `shared.fences_shared`, `"checkout"` in the reason, the planning writer already at the new tip, the foreign index bytes unchanged, and both the previous and advanced commits present under `refs/aitm/recovery`.

A successful fast-forward is `ContinuityStatus.VERIFIED`. `admit()` calls `_recovery()` only when `frontier.fences_shared` is true, and the `GitCommandError` / `OSError` / `ValueError` handler only rewrites the returned view to `blocked()` (`UNPROVABLE`). It does not create `refs/aitm/recovery/c08-…` refs. Nothing in `fetch.py` or `continuity.py` rechecks a worktree that appears during the compare-and-swap. If `update-ref` succeeds, the function returns the verified frontier and the new test fails. If a later error is raised after the ref moves, the writer can advance, but this leaf still does not retain both commits.

2. Explicit refresh does not use the preflight publication it just computed, so stale, unknown, fenced, and verified dispositions diverge from mutation.

`preflight_policy()` in `packages/aitm-core/src/aitm_core/services.py` sets `PublicationOutcome.PENDING` when code freshness is `STALE` or any shared status is not `LOCAL_ONLY` (including `VERIFIED`). `prepare_mutation()` keeps that result. Unit tests lock it in: reconciled verified observation stays pending, and unknown code never resolves a policy.

`_refresh_validation()` in `packages/aitm-core/src/aitm_core/cli/planning.py` always substitutes its own `incomplete` flag. That flag is only code `STALE`/`UNKNOWN`, shared `STALE`/`UNKNOWN`, or `local_diverged`. It ignores `preflight.publication`.

- Fresh code and a verified, non-diverged shared frontier: mutation returns `pending`; `planning validate --refresh` returns `not_applicable`.
- `Freshness.UNKNOWN` with no shared frontier: preflight returns `not_applicable` with `INTEGRITY_ERROR`; the CLI forces `pending`.
- `Freshness.FENCED` with a verified, non-diverged frontier: preflight stays `pending`; the CLI reports `not_applicable` because fenced is not in its set.

That is a second classifier on the route that was only supposed to add `--refresh`, `--installation`, and the typed preflight call.

### What holds

- `observe_shared()` and `unavailable_shared()` keep the trusted checkpoint for route mismatch, deletion, rollback, sibling, and unprovable ancestry. A failed content check quarantines the observed commit and does not move `valid_tip`. Transport loss does not clear a rollback or quarantine. A content-valid sibling never reaches content admission.
- Pending replay is bound to the last accepted journal frontier. `recover()` re-runs `observe_shared()` on that checkpoint and refuses the append when the tail does not match, including a content-valid sibling with its own transport ref. The journal parser rejects a partial tail, two uncommitted records, a missing journal with retained refs, a foreign route, and a writer move while fenced or diverged.
- Real ref updates are one `update-ref --stdin` transaction with `no-deref` and old/new values for checkpoint, valid tip, planning writer, and journal marker. The interrupted compare-and-swap test covers both sides of that call.
- Private planning candidates must match `refs/aitm/candidates/planning-` plus 32 hex digits. Fetches use `ls-remote` against the configured URL, `--refmap=`, and a direct-ref check before admission. Cached reads do not call the refresh port. Story `.aitm.toml` is not the policy source. The CLI test still names the committed policy tip after a story edit.
- `prepare_mutation()` checks the planning snapshot and the policy digest before `backend()` is constructed, and the guard rechecks the direct code pin. `load_installation()` rejects duplicate keys and a descriptor-supplied store. No predecessor test file is deleted in this diff. The candidate target in the supplied receipt is `codex/core-472-integration`, with base `18cddc2f2715cf19a2d27d8a8e78fc00c23f5f5d`.
