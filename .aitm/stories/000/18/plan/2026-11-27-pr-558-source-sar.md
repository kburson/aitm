Maximal prefix is the in-order walk, not the last cache entry. `P→V→B` leaves the trusted base at `V`. A child of `B` that restores `P`, or a receipt whose embedded prefix was rewritten to `P`, fails `_verify` because the recomputed receipt bytes and prefix entry map (receipt popped) must both match. `first_invalid` stays on `B`.

The default `ForwardRepairVerifier` is installed on `validate_history` and on `refresh` when the port is `"default"`. `aitm planning repair` calls `plan_repair` / `apply_repair`. The receipt binds store anchor, bad tip, prefix commit/tree, first offending commit, and that commit’s paths. It does not name the resulting commit or final tree. Acceptance still runs `_check_tree` on the restored tree, then normal rules after that commit. A forged receipt sets `repair_refused` and remains in history. A later child whose own recomputed receipt matches the same diagnosed prefix is accepted.

Unpublished work that is not an ancestor of the quarantined tip is kept under `refs/aitm/recovery/c10-<id>/…` before the branch CAS. The bad tip stays the repair’s only parent. Push is fast-forward with `--force-with-lease` to that tip. A failed or unacknowledged push leaves local `completed` and publication `pending`. The same expected tip retries the push. A fresh `planning validate --refresh` uses the same default verifier. Shared ancestry with the code ref still returns `code-ancestry` and is not repairable. Non-linear history, a missing prefix, and a mismatched quarantined tip are refused. The gate still enforces checkout exclusion and post-update worktree fencing. The C06 missing-verifier path remains an explicit `None` port.
