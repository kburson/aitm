## Pickup detail

Use U06 exact versioned rate API and U13 fixed ledger and scope interfaces. Own only export.py, cli.py and assigned test/receiver fixtures. Derive each normalized row from an exact as-of LedgerView and the explicitly selected supported rate card. Include stable immutable receiver source identity, observation and scope revisions, sanitized attribution and coverage, currency, explicit Unknown and rate basis. Do not serialize dataclasses wholesale. Replay at same cutoff is byte-identical even after later changes. Price/scoping changes preserve receiver identity and enter reconciliation. Safely publish complete snapshots with a manifest tying project, schema, cutoff, rate basis and JSONL digests. CLI opens existing private state lease-free.

Implement temporary SQLite C44 compatibility fixture with atomic acceptance/watermark and durable per-key pending/reconciliation state. The receiver rereads pending keys even after its watermark advances. Test interruption, restart, exact duplicate retries, changing selected rate card, late completion, scope correction, malformed or conflicting payload, stable as-of bytes, both JSONL and manifest privacy, and real CLI path. Actual C44 code and lifecycle stay outside scope. Estimate 3.5 agent-hours. Stop for estimate or ownership changes.

Resolve scope at the same fixed view as observations and derive exact scope/correction provenance from the existing resolver. An unbound or corrected record has explicit scope availability. Select current observations by key once. Keep independent account quota and billed availability out of C44 immutable usage payload identity, and never export quota as a debit. Use deterministic ordering and an explicit schema version. Avoid exposing project HMAC authentication material beyond the sanctioned pseudonymous export representation. Treat exported price as a pinned projection of the selected card, not a live account statement.

Use fresh temporary sibling publication, manifest validation and atomic complete visibility, or validate exact idempotent replay if a destination already holds the same output. Refuse conflicting destination or unsafe paths without partial overwrite. The receiver fixture checks normalized schema, project/version/rate/cutoff and row digests, exact closed keys and duplicate/source conflict semantics. Correction and pricing changes under an accepted source key belong in reconciliation; ineligible late changes may withdraw pending availability but never replace accepted bytes. Verify a prior cutoff is byte-identical after append, U06 and U13 survive unchanged, and the receiving fixture is only a model of #51's eventual seam.

Current U06 handoff projects the explicitly selected card through load_rate_card(version) and price(usage, card), using card.basis.identifier as the immutable versioned basis. Use that public seam once the U06 exact base is accepted. Source, scope and price availability are independent. A new selected rate basis creates distinct fixed output and becomes reconciliation for previously accepted keys. Do not conflate same-version revision, source observation revision, and ledger sequence.

Pin public reference form to hmac-sha256:<digest> for every exported source, scope and related SourceRef. Strip the private authentication tag and verify its absence with actual authenticated ledger refs across both files. Validate safe atomic no-clobber publication with a competing destination and symlink. Include allowlisted diagnostic/coverage summaries in the manifest, including gaps with no usage observation. These are separate from immutable C44 ingest payloads.

The receiver's durable accepted digest is immutable. Identical provenance and identical payload are a no-op. Identical provenance with different bytes is a conflict. A valid changed observation revision, scope revision or rate basis can enqueue a distinct reconciliation while preserving prior acceptance. Stale or out-of-order snapshots cannot regress the watermark or mutate newer pending/reconciliation state. Reconsider pending records on a newer snapshot regardless of previously advanced watermark. Test duplicate, conflicting, corrected, stale and pending states under restart.
