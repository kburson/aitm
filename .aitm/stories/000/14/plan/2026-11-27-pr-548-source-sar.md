**Registration.** `packages/aitm-core/src/aitm_core/ext/registry.py` selects only `policy.config.extensions.enabled`. Installed manifests get `ENABLED`, `DISABLED`, `INCOMPATIBLE`, or `MISSING` separately. Duplicate policy entries, names, namespaces, and the reserved `core` namespace raise `RegistrationError`. Dependency specifiers and `requires_core` use `packaging` `Version` and `SpecifierSet`. Enabled order comes from `TopologicalSorter` plus a namespace heap, so declaration order does not affect order. Cycles and missing, disabled, or incompatible dependencies fail closed. Capability, directive, event, producer, and init ids share one namespace check. Ids must start with the owning namespace. Duplicate ids are refused. `resolve` returns a registration only for an enabled owner at the requested version and placement. Disabled and incompatible owners stay visible with `registration is None`. A directive-kind `CapabilitySlot` without markdown raises `RegistrationError` and includes the slot id: `directive {registration.id} requires Markdown metadata`. Guards accept only `onEnter` and `onExit`. Actions and directives accept only `action`. Only actions carry `execution`. Activity contracts must match `_MEASUREMENT_CLASSES`. `load_extensions`, `resolve`, and `extension_status` do not call `cli_factory`, `backlog_factory`, `githost_factory`, or init factories. Discovery, mounting, setup, workflow parsing, and directive body reads are not in this leaf.

The negative cases cover a missing observation, a null commit, a different tip, the wrong ref, the wrong remote, a missing remote, a missing or different containment id, empty evidence, and `version` 2.
