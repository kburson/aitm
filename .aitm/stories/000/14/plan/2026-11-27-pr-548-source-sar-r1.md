## Independent verdict

CHANGES REQUIRED

The publication witness can be marked `verified` for a different commit than the publication candidate, and the test that should reject bad publication witnesses errors before those cases run.

### Blocking

1. `PublicationResult` does not bind the observed commit to `intent.candidate`.
In `packages/aitm-core/src/aitm_core/providers/githost.py`, `PublicationIntent` carries `candidate: Oid`, and the `verified` branch of `check_publication` requires a non-null `observed.observed_commit`, `contained_operation_id == intent.operation_id`, non-empty `evidence`, and a ref/remote match via `_check_observed_ref`. It never requires `observed.observed_commit == intent.candidate`. A result can therefore be `verified` while the observed tip is some other valid OID. That inflates `verified` past the exact target commit. `test_publication_verification_requires_the_observed_ref_and_operation_witness` in `packages/aitm-core/tests/unit/test_c13_providers.py` uses the same `HEAD` for both fields and never supplies a second valid OID.

2. That same test does not successfully assert the rejection cases.
The negative loop is `PublicationResult.model_validate({**dict(result), **overrides})` inside `pytest.raises(ValidationError)`. `PublicationResult` is a Pydantic v2 `BaseModel` (`extra="forbid"`, `frozen=True`, `strict=True`). `dict(result)` raises `TypeError` because the model is not a mapping. `ValidationError` does not catch that, so the overrides (missing observation, absent commit, wrong ref, wrong remote, wrong operation id, empty evidence, `version: 2`) never run. The happy-path `model_dump_json` round-trip above the loop is valid. The rejection contract is unproved.

### Checked and holding

Committed selection is separate from installed declarations. `load_extensions` in `packages/aitm-core/src/aitm_core/ext/registry.py` reads only `policy.config.extensions.enabled`. Statuses are `ENABLED`, `DISABLED`, `MISSING`, and `INCOMPATIBLE`. Duplicate policy names, duplicate extension names, and reserved or duplicate namespaces raise `RegistrationError`. Disabled and incompatible capabilities stay visible with `registration is None`.

Core and dependency versions use `packaging.version.Version` and `SpecifierSet`. Enabled dependencies are checked before a dependent is ordered. Cycles, duplicate dependency names, and missing, disabled, or incompatible targets fail closed. Ready nodes are ordered with a heap on namespace, so declaration order does not affect `ordered`. The test expects `("metrics", "hosting", "reports")`.

Registration ids are frozen and namespace-owned. `_declarations` requires `identifier.startswith(f"{namespace}.")`, reserves `core`, and rejects duplicate ids across slots, directives, events, activity producers, and init steps. Placements are unique. Guards only use `onEnter`/`onExit`. Actions and directives only use `action`. Only `kind="action"` may set `execution`. A bare `kind="directive"` slot fails closed. `DirectiveRegistration` keeps a `.md` path and does not read it.

Activity contracts are accepted only for the three `measurement_contract` / `coverage_class` pairs in `_MEASUREMENT_CLASSES`, and only from enabled extensions. `register_activity` requires that exact contract. `load_extensions`, `resolve`, and `extension_status` do not call `cli_factory`, `backlog_factory`, `githost_factory`, or init factories. The unit test records `calls == []` until the test itself calls the factory.

Backlog and Git host surfaces are protocols and frozen models only. There is no adapter and no network or Git call. `IdentityResult` status `issued` sets `pending_finalization` and must match `reservation.intent.issuer`. `uncertain` cannot carry `absence_proof`. Conclusive `BacklogObservation` values require evidence. `pending` and `unsupported` leave `is_present is None`. `LocalGraduationAuthority.graduate` takes the existing `FinalizationIntent`. `GraduationResult` exposes `issue` only when the command operation id matches and the publication outcome is authoritative (`VERIFIED` when `shared`, otherwise `NOT_APPLICABLE`).

`packages/aitm-core/pyproject.toml` adds `packaging>=26,<27`. The `uv.lock` hunks add only that runtime edge on `aitm-core`. No prior test or floor file is deleted. Discovery, setup execution, workflow parsing, profile graphs, and directive body resolution are not in this diff.
