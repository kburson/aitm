## Independent verdict

CHANGES REQUIRED. The pinned C19 diff does not meet the accepted discard contract: a failed attempt can wedge discard for good, a recycled document path can delete the wrong draft, and graduation refusal is narrower than the safety rule and can hide a committed retry.

Reviewed pinned head `ac95f99fa2292a29596a4a03c5913da2d3741b72` (tree `6b3115aaf878d0754bf48d839e855a02fffa1c61`) from the exact diff and the delivered dependency sources in the request. Happy-path Git coverage in `test_draft_identity` does establish live slug suffixes, ambiguous slug listing, identity disambiguation, one-commit removal with attachment and `prior_tree` hashes, tombstone suffix `-2`, same-reason retry by entity id, refusal of a one-line graduation file, and the remote attachment race. ## 1. High — uncommitted discard consumes the stable operation id

**Where:** `packages/aitm-core/src/aitm_core/drafts.py`, `Intake.discard_draft`, at `identity = f"draft-discard-{entity.ref.identity}"` and `Tombstone(..., discarded_at=self.stamp, prior_tree=self.snapshot.tree, ...)`. CLI stamp is `datetime.now(UTC)` in `packages/aitm-core/src/aitm_core/cli/drafts.py` `_apply`. Retain-before-commit is `CommandService.execute` in `services.py`: `publisher.retain_request(operation)` runs before `transact`, and `Publisher._retain_ref` raises `ReplayConflict` when that operation id is already pinned to a different blob. `ReplayConflict` is a `ValueError`, so `mutate` returns `LocalOutcome.UNAVAILABLE`.

**Failing scenario:** Planning remote is configured, as in the C19 topology. `discard_draft` retains `draft-discard-{identity}` whose payload includes `discarded_at` and `prior_tree`. A concurrent planning update wins compare-and-swap. `transact` returns conflict `snapshot-changed`. No tombstone and no operation receipt are written, and the draft stays live. The publication ref still names the uncommitted request. The next discard, including a CLI retry with the same reason, builds a new tombstone because the clock and the tree moved. `retain_request` raises `retained publication identity disagrees with the request`. The caller gets `UNAVAILABLE` ("Could not retain the publication request..."). Every later attempt repeats that failure, so the live draft cannot be discarded.

**Required outcome:** An attempt that does not commit must not pin `draft-discard-{identity}`. After this race, a later `discard_draft` of that same live draft with the same reason must commit, or, if a commit has landed, must return that completed operation. A committed discard must still retry as one stable operation id. Add a real Git test that forces the first attempt to retain and then lose compare-and-swap, then discards again and asserts the second result is not `UNAVAILABLE`.

## 2. High — discarded document paths are reissued and then act as live handles

**Where:** `Intake._create` allocates with `vacant_path` over `_entries` of the current tree only. `Intake.discard_draft` selects `handle in (e.ref.identity, e.ref.document)` before slug matching and before tombstones. Tombstones keep `entity.document`, but that path is not reserved.

**Failing scenario:** In one UTC minute, create "One idea" (identity A, document `.aitm/drafts/2026-11/20261127-1455-one-idea/draft.md`), discard A, then create "One idea" again. The folder is gone, so the second create gets identity B and the same document path. `discard_draft` of A's document path matches B and deletes B. A's tombstone still names that path. No ambiguity is reported.

**Required outcome:** A document path recorded on a live draft or a discard tombstone must not be allocated again. A discard handle equal to a tombstoned document path must resolve only to that tombstone's entity. It must not delete another live entity. Add a Git test for create, discard, same-minute recreate, and discard-by-old-path that shows the new draft's tree is unchanged.

## 3. High — a graduated draft is discarded when the graduation event is not line 0

**Where:** `Intake._graduated` uses `records = raw.splitlines()` and then only `validate_envelope(records[0])`. The discard read set built in `discard_draft` / `_apply` contains the draft folder and the new tombstone path, not the story log. Initial publish fast-forwards that commit. The new whole-tree replay guard in `packages/aitm-core/src/aitm_core/store/publication.py` (the `core.draft.created` / `core.draft.discarded` check just after the fresh-guard `ReplayConflict`) only stops a replay onto a different tree. It does not repair a discard that already treated the draft as not graduated.

**Failing scenario:** `.aitm/stories/.../events.jsonl` already has one valid event line. A later line is `core.story.graduated` with `source_kind == "draft"` and `source_id` equal to a live draft. `discard_draft` does not see that line, deletes the draft folder, writes a tombstone, and can fast-forward the shared branch. The current test overwrites `EVENTS` with a single dumped line, so this shape never runs.

**Required outcome:** Refuse discard when any record in any story `events.jsonl` is a `core.story.graduated` event for that draft identity. Leave the local tip and the remote planning ref unchanged. Add a Git test that appends the graduation event after an existing line and asserts `local == refused` and an unchanged tree.

## 4. Medium — a committed discard retry is refused once a graduation record exists

**Where:** `Intake.discard_draft` calls `_graduated(...)` and returns `REFUSED` / "The draft has graduated." before `if entity is None: return self._retry(...)`.

**Failing scenario:** Discard identity E with reason "Superseded" so the tombstone and the completed receipt exist and the folder is gone. Then write the same one-line graduation fixture the test already uses, with `source_id` E. `discard_draft(E, "Superseded")` returns `REFUSED` and does not return operation id `draft-discard-E`. The accepted retry rule is that the stable entity id returns the retained operation. The same call with handle `draft-discard-E` still reaches `_retry`, because that string is not the graduation `source_id`.

**Required outcome:** Same-reason retry of a retained tombstone returns that receipt's completed operation id and does not create a commit. Graduation refusal applies to a draft that is still live. A reason mismatch stays `CONFLICT` and names the retained operation id. Cover both with Git tests: discard, append graduation, retry by entity id; and retry with a different reason without a new commit.

## 5. Medium — any nested `draft.md` aborts discard of every draft

**Where:** `Intake._live` treats every path under `.aitm/drafts/` that ends in `/draft.md` as an entity, then constructs `EntityRef`. `EntityRef.check_document` accepts only a five-part `.aitm/drafts/{month}/{stem}/draft.md` path. Planning validation allows `.md` under `attachments`.

**Failing scenario:** A live draft has `attachments/draft.md` (or any deeper `draft.md`) with parseable bytes. `_live` raises `ValueError` while building the candidate list. `discard_draft` of a different healthy draft never runs. The CLI maps that to `INTEGRITY_ERROR`.

**Required outcome:** Only canonical idea and draft documents are live entities. Nested attachment paths are ignored. One attachment must not block discard of another draft. Add a Git test that discards a healthy draft while a sibling draft holds `attachments/draft.md`.
