Those receipts do not cover the post-CAS failure mapping.

1. `packages/aitm-core/src/aitm_core/store/git_backend.py:189-202` — After `compare_and_swap` succeeds, a tip that is no longer `candidate` is raised as `ValidationRejected` and caught at the `ValueError` handler. The caller receives `LocalOutcome.INTEGRITY_ERROR` bound to `current`, the preimage snapshot. The planning ref already holds the operation commit. The leaf requires that post-update recheck to retry within bounds or report contention with the retained inputs. `INTEGRITY_ERROR` is the wrong distinction, and the result drops the snapshot that won the CAS. The same handler is what a refusing gate uses before CAS (`test_validation_is_mandatory_and_refusal_preserves_ref`), so a pre-commit scope denial and a post-commit tip change share one outcome.

2. `packages/aitm-core/src/aitm_core/store/git_backend.py:152-155` and `git_backend.py:199-200` — `unknown-snapshot` runs only when `read_tree` returns a different `Snapshot`. A full-length revision that is absent fails inside `Repository.read_tree` as `GitCommandError` (`objects.py` `read_tree` / `_git`) and becomes `LocalOutcome.UNAVAILABLE`. A missing expected commit is an unknown snapshot, not an unavailable Git process.

3. `packages/aitm-core/tests/integration/test_c05.py:196-228` — `test_git_interruption_recovers_by_operation_identity` raises `Interrupted` (a `RuntimeError`) from `compare_and_swap`. That bypasses both handlers in `transact`, so the suite never observes a successful `update-ref` followed by a caught `ValueError`. Green `test_c05.py` plus the C04 names parametrized in `test_c05.py:132-176` leave finding 1 untested. `test_ref_cas_preserves_a_competing_update` covers only a CAS loss.

What holds: `read` / `read_tree` bind blob reads to one tree (`git_backend.py:87-93`, `objects.py` `read_blobs`); the index environment is stripped and index writes go to a temporary index (`objects.py` `_run`, `create_commit`); recovery reads `.aitm/operations/<sha256(operation id)>.json` from the tip and returns the recorded result when the request digest matches (`git_backend.py:102-119`); guard refusals with `evaluation.record` persist the record without applying `evaluation.writes` until the record blob is added (`git_backend.py:178-188`).
