## Architecture and authority

A trusted report process supplies a snapshot-bound list. Before executing candidate code, a controller must qualify a locally available, already governed execution boundary. The controller must own the assignment and evidence, remain outside candidate execution and write authority, and receive qualified independent observations. Candidate pytest evidence is corroboration. The accepted #353 finding permits cooperative feedback under a declared scope, while this story's strict result requires the independent boundary. A same-account subprocess, worker-owned pytest JSON, an executable named `dtrace`, and a historical hosted receipt each lack current qualification on their own.

The target is an ordinary local pre-commit command. The story leaves hosted PR selection and gate authority in their existing scope. The approved attempt requires no account, entitlement, privileged configuration, hosted runner, or credential changes. A separate operator-controlled environment can satisfy the boundary only when its current authority and exact inputs are available and evidenced.
