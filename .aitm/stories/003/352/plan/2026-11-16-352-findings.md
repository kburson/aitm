The canonical helper list includes `tools/ci/path_map.py`, so the inventory parser requires `tools/ci/tests/test_path_map.py` in the `ci-helpers` targets and as a module rule. The local suite policy lacks both declarations. The stock local planner refuses before collection and before selection. ## Handoff to #354

The probe supports reporting the mapped module and the 30 **pinned mapped obligations** from an independently admitted inventory on a bounded snapshot. The report must name its current effective snapshot, pinned trusted base, authority, changed path, mapped module and the reviewed inventory identity. Each prior ID is a pinned obligation. A fresh exact candidate inventory and a claim of complete impact are separate and require candidate-bound qualification.

An arbitrary edit at the same regular path, even with the same mode, can change imports, parametrization, collection or runtime dependencies. Path and mode equality, the base map and a previously matching module inventory do not establish the candidate's actual test IDs or a complete affected set. #354 needs checks that bound the supported change class and must label carried-forward obligations. It may claim exact candidate IDs only after an accepted candidate-bound inventory check for that scope. A report using pinned obligations can avoid executing test bodies or importing candidate Python. If an implementation loads candidate code for collection, it must declare and qualify that boundary.

Unknown inputs, additional changes, mode or path drift, changed tests or setup, and incomplete or out-of-scope evidence require full fallback where verified full obligations exist, or an unavailable result. An empty set cannot stand in for uncertainty. Keep the stock full-inventory path and arbitrary edits unqualified until evidence supports them.
