# #352 finding — the local snapshot sees the edit and the inventory gate refuses it

**Finding.** On current trunk, the first planning blocker after module startup is an inconsistent candidate suite policy. The canonical helper list includes `tools/ci/path_map.py`, so the inventory parser requires `tools/ci/tests/test_path_map.py` in the `ci-helpers` targets and as a module rule. The local suite policy lacks both declarations. The stock local planner refuses before collection and before selection. A separate startup defect makes the bare module invocation fail even earlier when `tools/ci` is absent from the import path.

## Handoff to #354

A trustworthy bounded list is supportable when an exact effective snapshot differs only at this regular audited input and the base-owned map, consumer scope, test module and associated inventory still match. The minimum result is a report tied to that snapshot with the changed path, mapped test module and the pinned node IDs it can justify. Plan the reporting surface and provenance before coding. A report can use an admitted inventory for this case without executing test bodies. An import/collection route that loads candidate Python must declare that behavior and its authority. Outside the demonstrated case, an unknown input, another change, mode or path drift, changed test or setup, and incomplete evidence require explicit full fallback when verified full obligations exist, or an unavailable result. An empty set cannot stand in for uncertainty. The stock full-inventory path needs its own qualification before it can broaden this witness.
