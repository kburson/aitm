## Scope and contract

- Keep hosted workflow, selector, map, and suite policy bytes untouched. Leave the stock full local inventory path outside this story. An unqualified full inventory cannot back a full fallback here.
- Support an effective single tracked regular modification of `packages/aitm-usage/src/aitm_usage/sources/grok_scope_hook.py` at the pinned baseline. The supported bytes are the exact audited base file followed by LF-terminated blank lines or ordinary standalone Python comment lines. Require at least one appended comment and preserve the original prefix and file mode. This scope preserves the probe's unexecuted, non-behavioral edit class and permits different comment text. It does not admit arbitrary behavioral changes, earlier-line edits, encodings changed through an earlier cookie, or appended Python. Restrict the suffix to ASCII comment text or blank LF lines. The [#352 probe](../../352/attachments/2026-11-16-352-selection-probe.json) is the positive replay; use its source and module paths and compare all 30 IDs.
- Require HEAD at the explicitly supplied qualified base commit. Allow staged and unstaged observations on the same path, including mixed staging, if the effective candidate matches the defined class. Require no distinct changed path across committed, staged or unstaged observations, including a staged extra path reverted in the worktree. Check the resolver's current effective identity again before emitting a positive report. The report binds an observed snapshot and includes that identity for a caller's own later revalidation. Clean, unsupported, drifted, or unqualified cases return `unavailable`.
- Use `python -E -m tools.ci.tia.working_tree_report --repo <target-checkout> --base <full-sha>` from a trusted tooling checkout. Document that the caller chooses and runs that trusted checkout. Require a full explicitly supplied commit ID and use `snapshot.LocalRequest` and `resolve`; do not interpret a branch name or current HEAD as trusted admission. Version 1 admits the exact witnessed baseline. A subsequent baseline can be qualified with separately reviewed evidence. Avoid runtime network, planning checkout dependencies, packaging/install changes, and pytest imports.
- JSON schema `aitm.tia-working-tree-report/v1`. A positive report exits 0 and uses `mode: pinned-mapped-obligations`. Emit the trusted base commit and tree, effective snapshot digest, path, mode, raw content SHA-256, audited consumer reason, mapped module, `inventory_sha256`, `inventory_source` and sorted `node_ids`. Carry forward the 30 IDs as reviewed pinned obligations. Use `candidate_inventory: unqualified` and `impact_completeness: unqualified`. Explicit `unavailable` exits 2 with a stable reason and no node IDs. A clean snapshot has no supported edit and a distinct reason. This command provides no test execution or pass/fail verdict.
- The pinned inventory is the uncompressed JSON from #344's attested live case #347, attempt `43882437964/2`, exact SHA-256 `812bc918dd9da7b413786454906d2ec8f486b5624bc8d1deecf9d546928d48e6`. Use its exact bytes in `tools/ci/tia/working_tree_obligations.json`. Validate hash, unique string node IDs, count 30 and exact module prefix. Resolve base map and audited base source from the baseline snapshot, read the consumer digest from the audited rule, and reuse `path_map.select` with the same before/candidate entry metadata as the probe. The base and the module must match the admitted reference. Transfer the 30 IDs only if the base selector returns the one audited module.
