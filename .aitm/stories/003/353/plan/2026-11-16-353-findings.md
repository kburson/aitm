# #353 finding — trust the observation boundary

**Finding.** The stock local controller launches a separate pytest process, but the pytest observer is a plugin in that process. The worker loads the candidate test code and the observer into one interpreter. The controller independently sees which process it launched and how it exited. The inventory, per-test phases and test-originated child rows come from inside the worker. Running the worker under the same local account also gives it the same filesystem authority. The stock route establishes cooperative local feedback. It cannot independently attest that arbitrary uncommitted Python executed every assigned test.

## Evidence

On trunk `8799c5a445dd4b51d499132e9a314b64796ae918`, [the launcher](https://github.com/kburson/aitm/blob/8799c5a445dd4b51d499132e9a314b64796ae918/tools/ci/tia/local.py) freezes a candidate copy, copies and hashes the observer from that snapshot, and sets the pytest evidence path and a scoped environment. It disables plugin autoload and passes `-p pytest_evidence` to the worker. `_Runtime.pytest` obtains the subprocess status and reads the report, and `_profile_result` reconciles reported IDs, phases, exit status and native children with the planned obligations. `_run` checks snapshot and copied-byte continuity. The observer records runtime hooks and writes its report at session finish. `record_child` receives the PID and status supplied through the test's observer path. A digest binds the copied bytes. It gives those bytes independent authority only when they are admitted from a trusted source outside the worker's authority. [Observer source](https://github.com/kburson/aitm/blob/8799c5a445dd4b51d499132e9a314b64796ae918/tools/ci/pytest_evidence.py).

[Machine receipt](../attachments/2026-11-16-353-process-probe.json) records a benign scratch probe with CPython 3.13.9, the locked pytest 9.2.0, and the exact stock observer. A parent launched one explicitly named node in each new child. A scratch hook confirmed the observer was registered and recorded the driver PID. Each called test independently recorded its PID as cooperative corroboration. Both matched the launched worker and differed from the controller. The effective account was shared. Each run used an empty output directory and the parent reaped the child.

| Assignment | OS child exit | Worker-reported evidence |
| --- | ---: | --- |
| One passing test | 0 | Exactly that node with setup, passing call and teardown |
| One failing test | 1 | Exactly that node with setup, failing call and teardown |
| Invalid node ID | 4 | No collection, phase reports or test body |

To reproduce, create a disposable folder outside the checkout and an empty pytest configuration. Define two plain scratch tests that write their PID to a per-run marker before one passes and one fails. A scratch `pytest_sessionfinish` hook can read the registered observer by name and record its own PID and effective account. Copy the pinned observer into a separate import directory. In a parent process, launch `python -P -m pytest -q -p pytest_evidence -p no:cacheprovider -c pytest.ini --rootdir . -- test_boundary.py::<node>` separately for each listed node. Set `PYTHONPATH` to the observer directory, `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1` and `AITM_CI_PYTEST_EVIDENCE` to a new receipt path for each run. Record the launched PID and wait status and compare with the markers, the collected list and the receipt phases. Use the pinned project lock with `uv sync --locked --no-install-project --python 3.13.9` and a disposable external environment.

## Handoff to #355

Require a controller outside the candidate's execution and write authority. It must bind the exact effective snapshot, reviewed launcher and observer inputs, exact planned and applicable mandatory test IDs, and fresh invocation before launch. Candidate code runs in a confined child under a boundary that protects controller inputs, verdict, and evidence custody. Separate directories and a separate PID under one account only give operational isolation. For a trusted positive result, require an admitted observation source that independently establishes the expected outcomes within the declared trust scope. Where a named test requires native child behavior, bind its observed origin and outcome to that assignment. Controller-observed exit is necessary process evidence, while the existing in-worker pytest report is corroboration.

Under cooperative reviewed-code scope, a local advisory verdict can join the real child exit to a complete matching receipt and report its limits. For strict trusted scope, the #355 plan must justify evidence ownership and demonstrate that the boundary rejects missing, stale or wrong-snapshot evidence, unexpected or missing IDs, ambiguous skips and incomplete phases, while preserving observed failures. A failure or absence of the independent boundary requires refusal for strict trusted execution. This research demonstrates an honest scoped subprocess and makes no claim of qualifying an independent production observer.
