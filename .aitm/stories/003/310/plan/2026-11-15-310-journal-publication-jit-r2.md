Frozen `_JournalDispute` holds exactly one `OwnershipDispute | ContentDispute`, a canonical storage identity `SourceRef`, a stored original-project UUID, and a lowercase 64-hex row digest. Add no required fields to existing constructors. Reject a dispute combined with coverage, disposition or paired. Leave existing disposition+paired behavior intact. Define frozen `PublicationCandidate(sequence, basis, identity)` with the closed basis strings coverage, ownership and content. No destination identity, consumer, quota, accounting payload, ACK or publication side effect.
- `RoutingJournal.dispute_changes(after_sequence)` validates a sequence in `[0, _tip(conn)]` in one existing read transaction. For ownership select `d.key,d.contender,c.project,d.digest,d.evidence,d.sequence,c.payload,c.digest` from `disputes d LEFT JOIN claims c ON c.key=d.key`. Use bounded sequence and optional exact claim key. Order by sequence, key, contender, digest, evidence. Refuse any missing claim rather than dropping it. Both schema foreign keys and storage protections remain. Validate `key` using the service key, canonical original-project and contender UUIDs, exact positive sequence and the lowercase 64-hex format of the contender material digest. Run `_stored_claim(c.payload,c.digest)` and validate the claim evidence and usage references with `types._encode` and the service validator. This rechecks the claim payload; `claims.project` itself is stored, like `as_of`, and is not sealed by that digest. Decode and re-encode exact contender evidence bytes with `types._decode` and `types._encode(..., ClaimEvidence, validate_ref=...)`. `d.digest` is the stored opaque digest for material no longer stored in that row. Prove format and exact membership only. Make no claim to recompute it or authenticate owner independently of journal custody.
- For content select `d.key,c.project,c.payload,c.digest,d.sequence,d.payload` from `content_disputes d LEFT JOIN claims c ON c.key=d.key` with equivalent bounded exact sequence/key predicates and order sequence,key. Refuse missing claim. Reuse `_stored_claim` and `_stored_content_dispute` and require the canonical `types._encode(..., _ContentDisputePayload)` UTF-8 bytes match the stored row. The row digest is SHA-256 of that exact raw canonical payload. Keep present `as_of` behavior, including row ordering. Identical checked bytes and single full row identity are needed for either dispute candidate.
- `RoutingJournal.publication_candidate(change)` opens one private read transaction. Require exact `JournalChange`, one of coverage or dispute exclusively, sequence as exact positive int up to tip. For a coverage change only recognized schema `_COVERAGE_SCHEMA_VERSION` and no future version qualifies. Use existing `_COVERAGE_ROWS` at exact sequence and require the sole committed v6 sealed row after `_stored_coverage` validation. Require canonical verified coverage equality. Refuse below the coverage version. Dispute read and issuance require recognized versions `_CONTENT_DISPUTE_SCHEMA_VERSION` through `_COVERAGE_SCHEMA_VERSION`, inclusive, using the existing store validator to refuse unrecognized versions. Both new dispute methods refuse below content-dispute floor. Query dispute candidate by exact sequence and key, produce checked wrappers from that snapshot, and require exactly one full typed, keyed and canonical match. Do not choose solely by sequence. Refuse substituted, future, foreign, ambiguous or malformed rows. Normalize input and stored validation `ValueError` and `LedgerError` to the same sanitized `LedgerError` refusal and preserve existing transaction/lease refusal behavior. Ordinary dispositions and paired settlements are outside this method.

## Versioned non-persisted identities

Use `self._store.evidence.pseudonymize` for both keys and `validate_source_ref` on the incoming candidate-relevant references. The input to pseudonymize is an ASCII JSON array produced by the standard library `json.dumps(values, ensure_ascii=True, separators=(",", ":"), allow_nan=False)`. Array order is the exact order shown. UUIDs use `str(UUID)` in canonical lowercase form. Sequences are JSON integers in decimal. Canonical codec bytes use UTF-8 then lowercase `.hex()`.

- Dispute row namespace `monitor-journal-dispute-row-v1`. Ownership input `["ownership", sequence, key.value, str(original_project), str(contender), stored_material_digest, canonical_evidence_bytes.hex()]`. Content input `["content", sequence, key.value, str(original_project), sha256(canonical_payload_bytes).hexdigest(), canonical_payload_bytes.hex()]`. The two types therefore cannot alias. Do not publish raw payload.
- Candidate namespace `monitor-journal-publication-v1`. Coverage input `["coverage", sequence, types._encode(verified_coverage, JournalCoverage, validate_ref=...).encode("utf-8").hex()]`. Dispute input `[basis, sequence, verified_dispute.identity.value]`, where basis is ownership or content and verified_dispute is recomputed from the exact stored row. The current service key isolates different journal identities. The same accepted bytes produce an identical candidate across reopen. The candidate contains the basis and sequence only with its keyed identity. No writes, sequence changes, schema bumps or key material are introduced.
