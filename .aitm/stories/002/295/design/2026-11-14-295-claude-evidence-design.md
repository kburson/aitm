# #295 ordinary Claude CLI evidence and durable journal cursor

## Substantive boundary

Qualify one opt-in, writer-supervised ordinary Claude Code CLI carrier on the pinned macOS arm64 build 2.1.318. The qualification workload uses a disposable project and three fresh, serialized tool-free invocations: pre-admission warmup, first admitted turn after arming, and one resumed measured turn. An admitted turn has exactly one prompt, one unique provider request, one terminal result and the required current quota observation. A failed or unsupported turn contributes a coverage gap and no new completed claim. Existing qualified providers, privacy-and-consent policies, receipt/ACK rules, journal fail-closed behavior, and R3 overlap holds do not change. #295 keeps its full R3 containment scope. This design is an additive prerequisite to its ordinary-prefix positive control, not a replacement for the overlap work or the downstream ACK/fence/report/export gates. No production enablement.

Prior probes established prospective normal capture admission, authentic transcript ancestry, the exact CLI completion and counters, same-run OTLP account and usage corroboration, and a private sealed join across reopen. Current journal calls still return no cursor. A typed carrier must close only explicitly matched existing diagnostic obligations; generic diagnostic suppression, synthetic terminal insertion into native files, fixture cursor seeding, and calling a private write method are disallowed.

## Authority and process custody

1. Require an explicit authorized launch. Reuse the current operator/project grant, registered checkout, approved source tuple, provider version, pinned transcript parent/file, and writer lease. The operator supplies a separate expected account authorization, identified privately in the service source-key namespace. Issue it only from current operator and project ledger custody, with a purpose, admitted source and installing tuple, exact authorization generation and expiry. An identity derived solely from a transcript or telemetry cannot authorize itself. Before initial qualification, learn the expected account through a separate authorized setup observation and have the operator select its keyed identity for the narrowly approved scratch project. The later measured process must match it independently in both native session-owner and exact-request OTLP. A conflicting later account, absent ownership, released writer or revoked consent fails. Retain account and organization references as keyed identifiers. Validate capture epoch, generation and prefix before the accounting route; a before-epoch warmup is evidence only.
2. The trusted monitor-side launcher starts the fixed, verified executable and holds the child's private stdin/stdout from creation to process exit. Bind launch identity, caller authorization generation, physical source registration, native session, and a fresh one-time run ID to the request before dispatch. The run has fresh private telemetry credentials, a restricted loopback receiver and a private replay record. Broker-owned code retains ordered allowlisted native events and no prompt or tool content. Same-user process compromise is outside the existing trust boundary; an arbitrary file, reused credential or exported local JSON is not authority. Fail closed on missing prompt echo, authentication, extra request, retry that changes cardinality, unexpected tools/subagents, out-of-bounds data or unexpected process exit. Keep this capability disabled for interactive, background, multi-request, cross-project or untested builds/surfaces.
3. For each eligible request, correlate echoed caller UUID to the unique native user row, native parent chain and native API request/assistant rows, and verify the exact assistant provider request ID, row UUID and message ID in the captured stdout. Match stream start and stop to that same message and require one successful result with no queued turn. Use the per-turn result counters and native cost-state difference for exact terminal reconciliation; check six token-category values (four base categories and two cache-write TTL splits) and apply the existing rate card separately. Join OTLP using provider request ID, native prompt ID and session, with exact account/organization and four usage counters. The OTLP client request ID and native internal requestRef are different namespaces. Require exactly one valid quota observation within the captured serialized turn interval under the existing quota shape validation and expected account. Retain it as an account-window observation, never as a turn-level cost.
4. The arm/enroll sequence must make the enrollment turn the first input of a new approved process as well, so the rate event from first launch does not disappear before the first eligible request. Arm on a genuine settled warmup prefix, then resume with one enrollment turn and secure all of its evidence. Verify and commit the existing capture epoch at its first eligible native boundary. Dispatch the next isolated measured invocation only after admission. Reconfirm every eligible native row and prefix obligation on the initial cold read. Demonstrate that the warmup was truly excluded and that every eligible request has either an accepted receipt or an explicit hold. This three-process prospective sequence is an acceptance experiment; prior scratch only proved the measured resumed turn and did not qualify the full cursor.

## Private proof lifecycle and routing

Use a writer-local opaque verified-evidence handle issued by the existing registry/scope authority, with exact source tuple, checkout/pinned root, native session and provider request ref, locator and incarnation, half-open native span, admitted generation, fixed prefix digest and original file identity, launcher run and current authority identifiers, typed normalized material, and a versioned keyed digest. Persist only normalized counters needed for reconciliation, keyed references and bounded authenticated commitments. No untrusted caller enters observations or clears a diagnostic by passing a boolean or file. On read, derive proof from privately captured material and replay against the original source. Keep account observation outside request accounting and do not modify historical prior usage.

Extend the existing Claude adapter/scope constructor path to receive optional writer-issued evidence for the exact committed native read. Match terminal reconciliation to that request only, and qualify quota only for an authenticated account interval and matching read. Retain all unrelated diagnostic instances, including generic coverage, ambiguity, malformed usage, scope/ownership problems, unknown remaining usage, and any failed terminal contributor. Apply normal claim logic, sequence and cursor completion via RoutingJournal.prepare, reserve_batch and cursor_for. Final transactional scope and authority readback must revalidate the exact joined proof, original admitted prefix and unchanged authorization before accepting progress. A persisted proof can be reissued after a fresh writer acquires and validates current authority; it is never equivalent to a live writer capability. Revocation, expiry and identity/source changes refuse new or replay-based advancement. Historical committed progress and earlier usage remain intact. Reopen must verify the durable claim and cursor; duplicate replay cannot add a claim or advance the cursor again.
