# #291 Disposable trunk hold rehearsal

The rehearsal used a synthetic public repository because GitHub refused ruleset access on the available private test repository's plan. The target contained a fixture, a normal pull-request check and a scoped ordinary-role probe. The production repository's effective rules and #103 controls matched the starting snapshots. [Disposable repository](https://github.com/kburson/aitm-stl-rehearsal-291)

The separate hold applied only to `refs/heads/trunk`. Its sole PR-only bypass was the rehearsal operator account. The independent normal ruleset required a pull request and a passing GitHub Actions `fixture-ci` on the current base. GitHub refused the operator role when the exact repair's normal check was red. The operator's direct push also failed. [Rules](effective-before-repair.json) · [Red repair refusal](operator-red-refusal.log)

The ordinary workflow used only its repository-scoped job token. It created an unheld branch and received provider denials for push, merge and ruleset edit on the held target. GitHub's rule evaluations show the ordinary PR and normal health check passing while the hold rule refused the merge. The same controls held after the nominated repair landed. [Initial role probe](https://github.com/kburson/aitm-stl-rehearsal-291/actions/runs/43718586152) · [Initial rule suite](rule-suite-5130601933.json) · [Post-repair role probe](https://github.com/kburson/aitm-stl-rehearsal-291/actions/runs/43718894462) · [Post-repair rule suite](rule-suite-5130629935.json)

Independent premerge review accepted the exact nomination for one simulated operator action. The provider recorded the operator role bypassing only the hold. Both normal rules passed, and the result matched the reviewed tree and the ordered base and head. The ruleset allows the operator account to bypass on any otherwise eligible PR. The exact single-repair choice was enforced by the rehearsal nomination and verified controller action. The administrative account was operated by the rehearsal script, and the experiment makes no claim of genuine human approval or production credential isolation. [Nomination](repair-nomination.json) · [Premerge review](repair-review.md) · [Verified repair](verified-repair.json) · [Operator rule suite](rule-suite-5130624236.json)

The existing shadow recovery store rejected a stale green for the old SHA. The fresh green for the repaired SHA left the shadow hold active until a simulated explicit operator acknowledgment. Exact disposable GitHub results supplied the replay inputs. The shadow attestation was a local projection of those results. After the rehearsal acknowledgment the operator role disabled only the disposable hold. The original normal rules remained active, and the ordinary PR was open and eligible under normal CI.
