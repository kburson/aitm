## Blocking findings

**B1. The full oracle is not one workload.** Step 2 requires “six explicit CI helper modules” and also “helpers from the pinned workflow contract.” The required #422 CI helper lane adds a category-sweep helper on top of the six-module TIA advisory contract. The plan also names two profiles, product tests and CLI smoke plus helpers, without stating that every case runs both profiles, how selected IDs are split across the two pytest invocations, or that published miss and fraction figures are the union of those profiles. An ID executed in the wrong invocation, or a seventh helper taken from the pin, changes the oracle. Fix: name the six advisory module paths, exclude the category-sweep helper from every oracle and selected lane, and pin the remaining argument vector at `45db935ac73911b95320a3e38d19f177cedd4fd2` (path plus blob, or a quoted argv). State that each profile is its own paired measurement and that scores are reported per profile and as the union.

**B2. The two-parent probe inputs are unbound.** The plan requires a literal two-parent synthetic merge and `tools.ci.tia.probe --parent --pr-head --tested-commit --tested-tree`, and it points at `origin/codex/403-shadow-run` for the pattern. It never maps those four values, never fixes parent order, and never defines the wrong tree. Fix, for every case: `--parent` is `45db935ac73911b95320a3e38d19f177cedd4fd2`; `--pr-head` is the single-variable candidate; `--tested-commit` is a merge whose first parent is that baseline and whose second parent is the candidate; `--tested-tree` is that merge’s tree. Record `git cat-file -p` of the merge. The clean control’s tested tree equals the baseline tree. The wrong-tree control reuses the clean tested commit with a different tree OID, expects `unavailable`, records no selected-ID sample, and reuses the clean full oracle.

**B3. Add, rename, and delete can be stacked, and their IDs are not sealed.** Rename and delete both say “that same test” after introducing a new name that is never given. That phrase allows a rename commit plus a delete of the replacement, which is two variables. The added and replacement node IDs are also absent from the predeclared table. Fix: three independent diffs from the baseline; delete removes `test_earlier_handoff_holds_later_handoff_with_stale_generation`; the added name and the replacement name are written down first; candidate collection is sealed before the probe receipt is opened.

**B4. Expectation sealing is specified for one case.** Only the transitive row freezes static consumer evidence and conftest reachability before the probe is read. Docs consumption, the shared fixture’s effect, and add/rename/delete inventories can still be written after the receipt exists. The section intro says the table is the human expectation, but the table has no literal IDs for new tests and explicitly allows the docs expectation to move after a consumption check. Fix: one sealed record per case, written before any probe output is opened, containing the necessary ID set, mandatory control IDs, predicted mode (`selected`, `full`, `no-tests`, `unavailable`), and the docs/conftest search result. Collection for that record uses pytest only.

**B5. “Full is defensible” does not score a miss, an over-select, or a save.** Transitive, shared, and dynamic all accept a full set. `no-tests` and `unavailable` are defined as modes, and the plan never says how they score when the full oracle has failures. Shared only says the fixture is “scoped” and “unused,” so an autouse fixture can turn a selection case into an outcome change. Fix with one rule set:

- Necessary set = sealed IDs (failure witnesses or the frozen static consumer set).
- Mandatory controls are allowed extras.
- Miss = a necessary ID omitted from the selected execution when the full oracle fails that ID or the seal marks it mandatory.
- Over-select = every selected ID outside necessary ∪ mandatory, including a full fallback. Defensible full selection is still over-select, and it is still recorded.
- `no-tests` with oracle failures is a miss of each omitted failing ID. `unavailable` has no miss rate and keeps the full oracle.
- Shared patch = one non-autouse fixture that no test requests. If that full oracle is not green relative to clean, the case is invalid.

**B6. The false-negative seeds contradict the clean control and have no identity.** The clean row requires seeded witness IDs to pass. Step 3 requires “two seeds” confirmed by exact failing node ID and assertion text against the clean baseline and the same-candidate oracle. No witness ID, fault diff, node ID, or assertion substring is named. A rerun is specified for the full lane only, so a one-sided flake can still be read as a catch or a miss. Fix: a seed table with witness IDs that pass on the clean full oracle, plus two fault injections with path, failing node ID, and assertion substring. Each fault fails with that signature on its full oracle and passes on the clean oracle. If the selected lane includes the ID and the signature disagrees, rerun both lanes once; if they still disagree, the case is inconclusive and is neither a miss nor a seed catch. If the selected lane omits the failing ID, it is a miss.

**B7. The leaf and transitive failure witnesses are not required to exist on Ubuntu.** Both behavioral witnesses are native watcher tests (`test_native_watch_reports_change_and_retires_resources`, and a `watched` root registration), while native macOS-only suites are placed outside the Linux contract. If Ubuntu skips those tests or the full oracle stays green, selection can be compared and a miss rate cannot. Fix: before any selector claim, the leaf full oracle on this runner must fail that startup-reason assertion, and the transitive full oracle must fail the `watched` registration assertion. If either failure is absent, that case is an invalid control and is omitted from the miss rate.

**B8. The dynamic patch is not a single resolvable procedure.** “The changed leaf” can mean `host_watch.py` or `scan.py`. “Nonliteral `importlib.import_module`” can be implemented as a constant string, which a static resolver can bind. No check requires the full oracle to stay behavior-identical to clean. Fix: patch only `src/aitm_usage/host_watch.py` at module scope; the module name is computed and evaluates to one named stdlib module; production behavior is otherwise untouched; the full-oracle outcome vector matches the clean oracle or the case is invalid. Score a full unresolved fallback as over-select against the leaf suite. Score a leaf-only selection as a soundness gap against the sealed rule that an unresolved loader cannot prove a safe subset, and report that no functional failure was available.

**B9. Savings can include queue, order, and an unstated formula.** Pairs share a runner and a worker policy, and planning overhead is in scope, but lane order, timer start and stop, and the arithmetic are open. One order warms the second lane. Queue time is outside the engaged-work estimate and can still enter “wall” time. Fix: declare order, or run both orders; start and stop on-runner clocks with queue excluded; state whether `uv sync` is inside the clock; record the runner image version. Use one published formula: `net = full_wall - selected_wall - plan_time`, `fraction = net / full_wall`, labeled single-shot. Keep the separate full-sized fallback lane even when it repeats the oracle.

**B10. Disposable-workflow safety is an end check, not an execution pin.** The plan forbids production CI edits, keeps an unmerged replacement draft, and later checks isolation. It does not pin the workflow blob, trigger, or token scope, and it does not retire remote candidate refs. A new workflow on the draft, a `pull_request_target` copy, or retained seed branches still satisfies the written steps. Fix: run the existing shadow workflow unchanged, identified by repo, ref, path, and blob SHA; contents read and artifact write only; no `pull_request_target` and no new secrets; auto-merge off; close the draft unmerged after archival; delete disposable refs after ZIP digests are recorded; show `main` and the required workflow blobs unchanged and the planning delivery limited to the #423 research record.

**B11. Closure has no minimum matrix.** Acceptance says missing provenance or an unexecuted minimum comparison leaves the work incomplete, and step 4 closes the issue after PASS and a Project Done read-back. The minimum set is not enumerable, so a partial case list can be archived. Fix: close only when each case has the patch, four Git identities from B2, hosted run/attempt/job, artifact ZIP digest, probe receipt, full-oracle receipt, selection-lane receipt or an explicit `unavailable`, sealed expectation, score row, and seed rows where required; plus the wrong-tree receipt, an independent recomputation from raw receipts, and an independent review PASS of those bytes and digests. Inconclusive rows may remain. Missing rows may not. Read back Project Done only after remote archival and the B10 isolation check.
