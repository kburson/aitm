# #434 Codex headless AIPR review-lock findings

**Disposition.** No tested route admitted a native Codex reviewer while preserving the sandbox and AIPR's lock ownership and process-incarnation checks. Both live macOS XPR fixtures stayed at `awaiting-reviewer` and their local brokers were offline on final readback. No sealed decisions were written. Two-round qualification, reviewer interruption and replay are pending a route that passes admission.

The November 24, 2026 probes used Codex CLI `0.171.0-alpha.13` with ChatGPT sign-in, AIPR `0.4.1` and Node `26.8.1` on macOS arm64. The disposable broker-owned XPR fixtures used a native Claude Code `2.1.331` author and a native Codex reviewer. Their installed AIPR code and owner checks were exercised as shipped.

## Implications for #426

- On macOS, the smallest AIPR-side candidate worth testing is a narrow broker-owned join and decision operation. It would verify the authenticated native reviewer binding and sealed invitation, enforce operation and destination scope, and run the existing lock and process-incarnation checks in the broker's host context. Admission would require proof of same-reviewer authority and protection against replays and ambiguous ownership. The disposable wrapper in this spike established no broker operation.
- Where a supported Linux host is available, rerun the native sandbox preflight and real XPR with the existing AIPR checks. Once either route admits a reviewer, verify two sealed decisions in one native session, an interrupted attempt with no premature decision, and replay with no duplicate decision or usage. Keep live, dead and ambiguous lock outcomes visible.
- Both macOS refusal turns produced native usage. The [companion receipt](codex-review-lock-receipt.json) records the native terminal totals and the corresponding retained rollout totals for each attempt, plus SHA-256 digests of the private native and AIPR logs. The stock attempt recorded 60,458 input and 349 output tokens. The scoped attempt recorded 93,157 input and 430 output tokens. Each input total includes cached input and each output total includes reasoning output. Attribute those counts to failed reviewer attempts if needed and keep them separate from orchestrator usage and sealed review receipts. The lightweight native Codex comparator in #430 provides a separate result and usage witness. Codex still has no sealed AIPR reviewer coverage in this spike. The spike did not measure billed charges.
