The 7 dropped nodes are folded scenarios, and they are the blocking failure.

It is an inline call inside `test_git_transaction`.
- `packages/aitm-core/tests/integration/test_c06.py` collapses the separate file-mode cases `120000`, `160000`, and `100755` into one loop in `test_tree_rejects_non_data_objects`. `test_checked_out_target_refuses_writes_but_review_ref_is_distinct` is deleted as a node and its assertions are prefixed onto `test_checkout_exclusion_before_and_during_publication`. A checkout failure now skips the publication-fence assertions.
- `packages/aitm-core/tests/integration/test_c07.py` deletes `test_only_validated_local_observation_can_select_policy` and `test_workflow_symlink_cannot_substitute_a_path` as nodes. Both bodies are appended to `test_policy_authority`, so a failure in the earlier authority assertions skips candidate routing and the regular-file symlink refusal.

Real Git ref and recovery contracts moved onto `CommitStore`.

- The integration copy of `test_advance_after_successful_cas_retains_committed_snapshot` is gone. The unit replacement in `packages/aitm-core/tests/unit/test_c05.py` patches `CommitStore.compare_and_swap` and builds `GitBackend` around that fake. `Repository.compare_and_swap`, the real ref advance, the parent check, and the retained `project.readback` retry no longer run against Git.
- `test_validation_is_mandatory_and_refusal_preserves_ref` is likewise only on `CommitStore`. `assert backend.snapshot() == start` no longer reads a Git ref. The `TypeError` for a missing gate still runs, but it does not preserve the ref contract named in the acceptance criteria.

The integration file still rejects `read_tree("0" * repo.oid_length)` with `UnknownTree`, and that is a different call from `transact` returning `unknown-snapshot` while the real snapshot stays put.
