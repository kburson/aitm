# #427 Interactive self-report evidence

Run on macOS on 2026-11-24. Codex CLI 0.171.0-alpha.13 using ChatGPT sign-in, Claude Code 2.1.318 using Claude Pro, and Grok Build 1.0.92 using the installed account session. The Grok launcher reported 1.0.77 before initial startup and updated to 1.0.92. The measured run used 1.0.92 with auto-update disabled. Usage fields are native measurements or native cost indicators. No billed dollar amount was independently verified.

## Method

Open an interactive TUI with a private pseudo-terminal. Complete three short deterministic text turns with tools and delegation unused. Turn 1 is an unrelated baseline. After turn 1, the test driver arms the assignment to the exact session and submits two story prompts. Accept only the expected synthetic answers. Close after the second assigned answer with no further model request. The test driver stands in for the orchestration control layer. No human copied numbers. Startup tuning used a disposable Grok/Codex directory and the already trusted AITM workspace for Claude with CLI settings supplied for this session and agent tools disabled. No persistent capture service or production integration was deployed.

## Outcomes

- **Codex TUI — demonstrated for a session launched with its callback.** The native `notify` event supplied the exact thread and turn IDs without usage fields. The first callback recorded identity only, so its usage observation count was zero by construction. A second run had the callback open the single matching retained rollout in that day's envelope and match its native turn ID and completion. It obtained terminal usage in three of three turns. The receipt shows a single matching source, pseudonymous native start and completion references, and time from native completion to callback start. This timing excludes the local file read. The assigned turns recorded 25,069 and 25,123 total tokens. The unassigned baseline recorded 25,015 and is excluded. The active Codex Desktop chat exposed its own thread identity and had a matching local retained path. Installing or enabling a completion callback in that already-open Desktop chat was not demonstrated.
- **Claude Code interactive — demonstrated with a bounded settle step.** Native `Stop` carried session, prompt, and transcript identity and no usage counters. A synchronous callback saw 0, 1, then 2 distinct request observations at the three stops, so reading synchronously would miss the final turn. A new three-turn session registered an asynchronous Stop callback with a one-second wait and then read its own exact transcript. It saw 1, 2, then 3 cumulative observations. The retained requests match those observations and resolve to the expected prompt by native parent links. The last request was captured without another model turn. The receipt distinguishes the synchronous and asynchronous sessions. This proves one sequential sample. A fixed wait has no guaranteed flush latency, and multi-request/nested turns or prompt-to-record binding beyond serial order need separate proof.
- **Grok TUI — demonstrated through a native one-shot command.** The test driver invoked `grok usage <session-id> <turn-number>` while the TUI was still open after each answer. The command returned a single matching turn with model, token categories, and native `costUsdTicks` in an envelope that also carried session aggregates. The receipt retains the selected turn rows. Turns 2 and 3 returned 18,902 and 19,015 total tokens and 34,979,200 and 34,102,000 native USD ticks. The assigned total excludes baseline turn 1. The experiment did not establish that Grok TUI emits a callable native completion hook for this route.

The three positive paths rely on a session-local callback or an exact-session call by the assigned control layer. Installing a callback dynamically in an arbitrary already-open chat and autonomous self-enrollment from conversational text alone were not demonstrated. Because the workloads were direct-only, the measured values belong to the root agent in each test. They do not establish delegation coverage. See [sanitized receipt](interactive-receipt.json).
