# #430 Result and usage correlation on native AIPR reviewer routes

## Disposition

**Claude Code and Grok Build passed for two completed review rounds.** Both reviews used the installed AIPR 0.4.1 project-local broker, manual transport and no-commit test mode. Each AIPR decision and its native usage belong to the same identified reviewer turn. Each route also demonstrated a joined, interrupted attempt with no sealed decision. **Codex could not join the actual XPR as a headless reviewer under the tested macOS workspace sandbox.** Its native refusal and interruption were measurable at the process boundary, but there is no Codex AIPR review result to correlate.

These disposable local macOS tests used existing signed-in provider accounts and no separately supplied API keys. Claude was 2.1.331, Grok Build 1.0.92, and Codex CLI 0.171.0-alpha.13. The fixtures exercised direct reviewer work with tool calls. Nested delegation, alternate metered routes, provider credit changes and billed spend were outside the evidence. Each case has a small sample on these installed builds.

## Method

A synthetic spec omitted the migration rule for preexisting exports. A separate reviewer requested changes. The author added a backfill rule and resumed the same reviewer; the reviewer accepted. Both completed no-commit reviews reached `accepted-uncommitted`. A separate fixture for each working route was interrupted after native output and creation of the pending response following the AIPR join. No on-disk reviewer response text or launch acknowledgement counted as a decision. A sealed decision required the AIPR event, actor fingerprint and response digest to agree.

For Claude, a private stdout tee passed the original bytes to the supported `peer-review launch-reviewer` CLI unchanged while retaining the provider JSONL for measurement. It also forwarded signals and was scoped to the fixture. Grok used the AIPR manual invitation and native `grok --single --output-format streaming-json` route, then explicit native resume. Its pipe captured the same native output used by the reviewer. For completed turns, the adapter located the successful native submit tool result before the terminal usage event. Exact source readback added no model turn.

The [sanitized receipt](xpr-turn-receipt.json) preserves pseudonymous identities and native counters. Raw streams, paths, protocol identities and transcripts stayed private.

## What the integration changes

- The AIPR response and provider settlement are separate events. On Claude and Grok, the authoritative submit succeeded inside the reviewer turn before the terminal usage record. AIPR's public Claude launch result reported `submitted` and identified the review and participant, while usage remained in the provider stream. The terminal usage includes work after submit that still belongs to the same native turn. Bind the full assigned turn and make its usage available after settlement.
- Claude's streamed assistant blocks carried stable request IDs. In both successful rounds, output counts read from the assistant blocks alone were lower than the final retained request values. Prefer the terminal per-result delta or reconcile deduplicated final request records. The interruption in this test retained a numeric partial terminal reading. #429's short interrupted prompts sometimes zeroed top-level usage, which reinforces using explicit field provenance.
- Grok's default compatibility scan loaded a Claude hook that rejected the Grok invocation for missing Claude authority. The targeted retry scoped `GROK_CLAUDE_HOOKS_ENABLED=false` to the disposable Grok processes, leaving the native Grok participant identity in place. AIPR labeled its model identity declared. The adapter independently verified the actual model in the native usage record and matched the provider session fingerprint. The blocked configuration probe ran in a separate native session and was excluded from the two-round totals.
- The first attempted Claude-authored Codex review inherited Codex identity variables from its parent process and AIPR classified it as SPR. It was excluded. Removing the foreign variables before launching the real Claude author produced the intended Claude-to-Codex XPR. An explicit provider binding and correct environment provenance matter even with exact model IDs. The disposable brokers subsequently reported offline. In the interrupted Claude fixture, AIPR refused suspension with an outcome-unknown error and the private state was preserved. The adapter did not replay that launch.

## Smallest handoff for #431

The caller should allocate the review-round attempt ID before launch. Return the sealed response or a typed missing/refused outcome together with the native session and turn or prompt identity, the raw usage categories or a pointer to their receipt, and the settlement status. For a late terminal, reconcile that exact attempt without calling the reviewer again. Keep native usage and billing estimates distinguishable from verified spend. Claude and Grok have demonstrated process-level paths for this approach. Codex needs a supported broker/lock route on its reviewer host before #431 can claim a real AIPR proof for that provider.

## Lightweight comparison

A disposable Codex control handed the reviewer the exact synthetic artifact and a small assignment containing review reference, round and artifact SHA-256. It carried two structured review results through one native session, echoed the assignment identity, and verified the stdout completion counters against exact retained turn IDs. The decisions were revisions-requested and then accepted. This validates a small measurement contract and the usefulness of doing coordination outside the model loop. It was a native comparison without AIPR claims, sealed responses, broker ownership or consensus authority. The different prompts and tool workloads do not establish a cost savings ratio.

For a later AIPR design, test whether the caller can own the immutable artifact/attempt envelope and capture native settlement as data while the reviewer only evaluates the artifact. Preserve a scoped review authority and distinct reviewer identity in any workflow that uses the result for delivery. The experiment made no changes to AIPR.
