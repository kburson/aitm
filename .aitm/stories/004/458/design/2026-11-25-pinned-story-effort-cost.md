## Immutable inputs and report identity

The caller supplies the verified full planning commit ID, project UUID, story number, UTC usage cutoff, and the exact reviewed rate-card digest. Resolve receipt inputs only through that Git tree. Pin selected receipt path, blob SHA-256, opaque identity and revision. Verify story frontmatter, expected project, normal tree modes, canonical allowlisted receipt shape, scope, and complete previous-revision byte lineage. Malformed or conflicting evidence fails closed. Select the highest eligible contiguous revision per identity within the cutoff. Use the receipt's UTC observation time and an inclusive cutoff. A newer tree or correction may change a new report only. A revision whose predecessor falls after the cutoff is ineligible and creates a visible coverage gap. Preserve selection rationale for excluded input. Reopening a report never resolves a mutable branch or silently fills from newer inputs.

Use a canonical, versioned report envelope with the pinned input manifest, report data, frozen human-readable output, renderer version and each component digest. Derive a content-addressed identifier from canonical bytes. Publish it as a new file under the story's effort reports directory. Same identity and same bytes are a no-op. A conflict holds. Reopen by the caller-supplied ID against the exact Git artifact, check the identity and component digests, and return the frozen bytes. Missing, tampered or unsupported evidence returns a stable explicit unavailable result. Do not rerender an old report with a later renderer. Publication uses the planning branch's existing authorization and protected nonforced path, with independent readback of the exact file.

## Coverage and time

Read a story-scoped, registered coverage record at the same planning pin, when one exists. It provides the independently verified expected attempt set through the cutoff, explicit pending or missing outcomes, and an unattributed count or gap from the bounded collection. Link the record through a `core.evidence.recorded` fact that binds story, relative path, cutoff and digest. The owning caller attests the bounded admission set and whether it is closed. Require exact opaque attempt correspondence to receipts before declaring the denominator complete. No record, an open admission set or unmatched evidence means an unknown or incomplete denominator. A receipt count is a measured numerator. Pending, missing, disputed and unattributed coverage are visible with their actual provenance. Keep project-wide unattributed observations outside story spend. A verified no-work declaration is distinct from absent evidence.

Reuse the #443 disjoint/inclusive aggregation rules. Bounded resolved usage contributes once. Inclusive, disputed or unproven scope stays visible and outside additive token and price totals unless existing verified overlap evidence proves the selected contribution disjoint. The report shows independently known cached input, new input (gross less cached plus applicable write tokens), and output (including reasoning when included by the provider). Label partial totals and expose per-column coverage. Preserve the distinction between no observations, unknown values and evidenced zero.

Show agent engagement separately from time spent waiting on a person, calendar elapsed and the existing Actual projection. Use #442 and #181 time rules, including unioning intervals per verified actor and clock domain and summing different actors. Where published receipt fields cannot prove shared actor, clock or owner-wait boundaries, show the known engagement with its coverage and leave the affected aggregate unknown. A complete price never qualifies a time measurement. A complete time measurement never qualifies price.

## Pricing and projection

Use exact request counters where the receipt provides them. Pin a canonical, versioned Standard USD comparison card to reviewed official provider evidence and a digest. Make tier and context-band rules part of that card. Match provider, exact model and supported counters. Validate per-request reconciliation to settled totals, including cached reads, cache writes and reasoning semantics. Reuse the known pure pricing operations where the source and accounting rules match. Keep the previous monitor's rate-card allowlist and historical formulas intact. An unsupported model, ambiguous context band, missing request breakdown or unverified counter yields Unknown with a reason. Explicitly distinguish a Standard API list-price reference from the actual service tier or charges.

Display provider-reported amounts, known API-equivalent estimates, and verified billed amounts as distinct columns with coverage. Grok native ticks are provider evidence. They cannot substitute for a reviewed API comparison or billing. Only admit verified billing from separately authenticated, story-attributable evidence with an exact cutoff. If the current producer supplies none, display Unknown.

Emit a Project Cost projection only when authorization binds the verified report identity, story, selector and scope, the bounded expected set is closed, every expected attempt is resolved and accounted once, usage and price are complete at the pinned comparison basis, and no pending, missing, unattributed, disputed or overlapping exposure affects the total. Return a hold with precise coverage reasons otherwise. Partial report publication remains usable and can include a known priced subtotal. No partial amount is projected as complete Project Cost.

## Acceptance scenarios

- Reopen a real published report from a fresh process and compare both output representations with the first build. Verify the protected report file and frozen receipt/rate/coverage pins independently.
- A late arrival, time correction, updated coverage roster, or reviewed rate revision produces a new report. Reopening the old ID preserves wording and bytes. A removed or corrupt pinned envelope returns unavailable.
- Cover missing coverage authority, expected pending and missing turns, unattributed scope, inclusive overlap, interrupted partial observations, exact zero, and valid complete pricing. Prove every coverage gap blocks Project Cost while leaving the report readable.
- Refuse noncanonical receipt bytes, wrong project/story, duplicate or broken revision identity, regressed or cutoff-crossing lineage, malformed rate input, unsupported model and path substitution. Verify privacy canaries and bounded input reads.
- Repeating the build against identical pins and replaying publication produce one report identity and zero duplicate registrations. Preserve focused tests, portable fixture CI and an independent review of the exact source before delivery.
