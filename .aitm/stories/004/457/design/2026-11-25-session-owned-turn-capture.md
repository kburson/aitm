# Session-owned agent turn capture

Status: proposed for #457. The owner approved the delivery direction in #455. This document specifies the first story’s capture and publication boundaries.

## Session and attribution

The operator’s live agent selects an active project and story explicitly. The enrolled session has a private durable handle and a verified planning remote. At turn start or before dispatch, the session stores the immutable project, story, role and attempt assignment using the existing effort enrollment and scope-marker model. Supported roles include the live agent, supervised headless workers, app subagents, SPR and XPR. Record a pending expectation before a dispatch can run. When the harness supplies an exact native reference later, attach it to that expectation with the verified launch or review binding. The current story affects future enrollments only. Changing the selection, a handoff, or fresh-session recovery cannot rewrite an existing assignment.

A caller-owned helper runs on documented, verified lifecycle boundaries. The live agent can invoke the same helper explicitly for recovery. Native parent/child linkage, an exact launched-process reference, or a verified AIPR attempt binding must tie a reference to the original expectation. Matching by timestamp, directory, or model cannot establish that link. The helper restores a named enrollment and reads only its bounded, authorized native evidence. It uses exact provider identity and attempt lineage. Ambient sessions, latest-file heuristics and shared provider-history sweeps are outside the capture surface. A provider callback or CLI completion can reconcile a receipt without asking a model to report its own tokens. Separate AIPR sealed decision authority from native usage settlement. Missing identity or evidence leaves the expectation visibly pending or unavailable. Unattached activity stays private and unclaimed until exact evidence proves its origin.

## Private recovery and planning publication

Extend the #435 effort store and adapters where their enrollment, exact-read and revision semantics apply. The private store contains the enrollment and launch binding, exact reference, observation cutoff, and pending settlement state. Use a transactional transition so a crash can resume from the same expectation without relaunching work. Respect existing revision and overlap rules. Restart and replay must produce the same settled usage contribution, including when a child finishes after its parent exits or a later revision arrives first.

Publish an allowlisted receipt per story and revision. Include opaque stable identifiers, provider/model where evidenced, role, time basis, native engagement and token categories when observed, coverage state and evidence digests. Preserve per-request rate inputs or an equivalent verified breakdown where the native source supplies them. Exclude provider identifiers, prompts, responses, local paths, sensitive environment values and pseudonymization material. Store pending and unavailable coverage separately from observed token totals. Use the released rollup's disjoint and inclusive usage rules so an inclusive parent does not duplicate a child. #458 owns pinned story reporting and rates. #459 owns Core export qualification.

A single project-scoped publication path targets the configured planning ref with existing branch protection. Independent processes can prepare immutable receipts. The scoped writer serializes registration within a publication batch and verifies the current remote tip. On a stale push, refetch and replay disjoint entries. On a lost acknowledgement, read back the intended receipt identities and digests before retrying. A same-key, same-byte replay is a no-op. A same-key conflict is a hold with both versions preserved privately. Never force-push. Use the repository’s existing authorized planning writer. If the live agent’s direct push is refused, the helper retains the receipt and hands the same scoped publication batch to an already authorized writer if one is available. A policy refusal without an authorized write path leaves remote publication unqualified.

## Qualification and boundaries

| Surface | Proof required for an advertised route |
| --- | --- |
| Codex desktop orchestrator and supervised app subagent | Exact start, completion or observable interruption, private recovery by immutable reference, and delayed attribution across a story switch. Report the sealed Codex AIPR decision gap separately. |
| Codex headless and same-provider review | Pre-dispatch enrollment, exact launched-attempt binding and bounded completion/readback. |
| Claude Code and Grok Build supervised native routes | Automatic observation on the supported lifecycle boundary and exact delayed recovery. For AIPR attempts, demonstrate independent usage readback with the correct sealed attempt binding. State the product surface, build and OS for each result. |
| Replay, privacy and remote publication | Exercise interruption, owner restart, resume or compaction, handoff, out-of-order settlement, pending and unattached controls, overlap, cross-project isolation, private-data canaries, concurrent pushes and ambiguous acknowledgement. |

Start qualification with the documented macOS routes and fixtures from #445 and #455. Acceptance requires automatic capture and exact delayed recovery for the Codex desktop owner and supervised app subagent, the bounded Codex headless path, and at least one supported supervised route each for Claude Code and Grok Build. Demonstrate same-provider review attribution and at least one sealed XPR usage association where supported. A required route that only passes manual recovery keeps its acceptance item open. For each provider, record the route, build, platform, automatic result, exact recovery result, coverage gaps and timings. Advertise additional routes only once their boundaries pass. If no supported lifecycle signal exists for a route, document the gap and any verified manual recovery. A manual read does not qualify automatic capture. Preserve Linux Grok as a separate qualification claim if exercised. Time normalization, private persistence, remote publication and recovery separately from provider execution. Count any additional model calls attributable to the capture path. Deliver the route matrix, sanitized receipts and remote readback against a real enrolled story with its authorization intact.

Implementation choices still open include the helper’s command shape and local directory layout. Pick the smallest extension of the published effort CLI and store that satisfies the boundary above.
