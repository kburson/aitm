# Agent-owned closeout qualification plan

**Goal.** Determine whether the Codex Desktop chat agent can settle and publish its own completed work and one supervised child at ordinary story closeout.

**Approach.** Reuse the trusted disposable #457 composer route, a bounded #461 enrollment and the shipped caller-owned effort CLI. Deliver the evidence and recommendation to `origin/planning`. This operational spike proposes no product changes.

**Scope.** [Refined story](../story.md) and [#457 composer qualification](../../457/attachments/qualification/457-desktop-forwarded-route.md). Pin source to the shipped #457 merge `87bc3d8a2875884014b59281117f68b9d63fabee`. Verify the active hook configuration, wrapper and loaded wheel bytes against the #457 qualification; compare the relevant installed wheel source with the shipped source. Use the existing disposable chat and current trust, separate from the normal checkout. Stop the live leg if any pin, thread, or trust check differs, and record what must be resolved before retrying. Preserve existing hook trust. Desktop composer entry may need a user to submit the scoped prompts. Record each submission and any other intervention. Keep the store, attempt IDs, native logs, command config and auth material private. Use #458 solely as the later selection in the isolated store.

## Execution

1. **Preflight and enroll.** Get cross-provider review on the exact plan before running the spike. Verify the disposable thread, the scope and digest of the established hook route, the supported CLI, the #461 and #458 planning story files, and the fetch/push URL and active branch rules. Record a store and remote baseline. Use `session-select SESSION 461 CAPTURE_REMOTE --epic 456` in the private store. The existing capture database is pinned to the isolated qualification repository. Keep that binding and use an independent writer-context database with the same project UUID and the existing authorized planning origin for Step 3. Use the Desktop composer to launch one short owner turn with one supervised benign child. The owner should wait for the child and end. Inspect only new exact callback references. A pending terminal callback means the callback is durably saved, adapter exit is 3, and the store has no receipt for that attempt at baseline readback. Native retention must subsequently supply the exact retry evidence. Allow at most one additional composer attempt if no pending terminal callback is observed. Record both attempts, retry only the designated pair, and report delayed settlement unqualified if neither run exhibits pending evidence.
2. **Switch and settle.** Give the same Desktop agent one closeout turn. It selects #458 for future work and launches fresh CLI processes to read status and retry the exact prior child and owner using `session-codex-hook SESSION THREAD ACCOUNT ROLLOUT_ROOT --retry ATTEMPT`. Preserve callback ordering and individual exit codes. Confirm the original two attempts still bind to #461, with an exact native parent/child correlation and one receipt per attempt. The closeout invocation itself belongs to a later turn and may require a subsequent settlement. Report the cutoff and any explicit attribution of extra turns.
3. **Hold and publish.** The same Desktop agent freezes `session-export-batch SESSION 461` to a private file and checks that it contains precisely the expected two roles, unique first-revision identities, #461 and approved sanitized fields. Use `session-publish-batch 461 REPOSITORY BATCH` from the preconfigured writer context. The owner's instruction to deliver #461 authorizes these two sanitized receipts. Confirm the exact writer repository, pinned fetch and push URL, current branch rules, and authentication available to that process before invoking the live write. First present the same batch using a local checkout with an unmatched `file:` origin. Require the shipped writer's remote-identity guard to return a hold, the batch bytes to remain identical, and the protected remote to have neither receipt. This is an origin refusal control. Run the shipped lost-acknowledgement and bounded-push policy tests separately for controlled transport uncertainty. For the live attempt, independently fetch planning and compare both mode-100644 paths and exact SHA-256 bytes, scanning both identities across all story receipt paths. If an ACK or readback is uncertain, preserve the frozen batch and reconcile by fresh authorized remote readback. Hold if readback remains unavailable. If readback finds a partial or conflicting result, record exactly what landed and stop live writes for disposition. Published receipts are immutable. Once the first readback verifies both paths, replay the exact frozen batch once and verify identical bytes and counts, no receipt-path change, and zero assignments to #458. Record the actual process and writer identity. If the Desktop agent lacks the existing writer capability, exercise sanctioned transfer of the same frozen batch to the existing writer and report assisted publication.
4. **Verify unresolved attribution.** In a separate private database and session, use the exact observed child start and terminal reference as control inputs with the owner-start event omitted. Feed the shipped hook CLI a child start and the retained terminal reference, select #458 and retry the exact child in a fresh process. Verify status still has a pending binding, a retained callback is available, the enrollment has null story and parent, and both story exports are empty. Avoid copying other callbacks or editing the live database. A focused fixture fallback demonstrates component behavior and earns a partial verdict for this leg.
5. **Deliver.** Record commands with private operands redacted, tool elapsed times, additional model turns, native timing and token splits where available, provider cost versus verified billing, operator actions, replay evidence, and a minimal closeout recommendation. Record a separate pass, fail, partial or unrun verdict for each leg, including any required human action and remaining gap. Restore the disposable store's prior selection. Obtain independent review of the pinned evidence, verify it on remote planning, record retrospective and cost evidence, then reconcile GitHub and Project 24. There is no source PR for this spike.
