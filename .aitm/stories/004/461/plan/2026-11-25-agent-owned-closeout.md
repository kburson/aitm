# Agent-owned closeout qualification plan

**Goal.** Determine whether the Codex Desktop chat agent can settle and publish its own completed work and one supervised child at ordinary story closeout.

**Approach.** Reuse the trusted disposable #457 composer route, a bounded #461 enrollment and the shipped caller-owned effort CLI. Deliver the evidence and recommendation to `origin/planning`. This operational spike proposes no product changes.

**Scope.** [Refined story](../story.md) and [#457 composer qualification](../../457/attachments/qualification/457-desktop-forwarded-route.md). Pin source to the shipped #457 merge `87bc3d8a2875884014b59281117f68b9d63fabee`. Verify the active hook configuration, wrapper and loaded wheel bytes against the #457 qualification; compare the relevant installed wheel source with the shipped source. Use the existing disposable chat and current trust, separate from the normal checkout. Stop and record any required local consent if reuse requires trust changes. Keep the store, attempt IDs, native logs, command config and auth material private. Use #458 solely as the later selection in the isolated store.

## Execution

1. **Preflight and enroll.** Get cross-provider review on the exact plan before running the spike. Verify the disposable thread, the scope and digest of the established hook route, the supported CLI, the #461 and #458 planning story files, and the fetch/push URL and active branch rules. Record a store and remote baseline. Use `session-select SESSION 461 REMOTE --epic 456` in the private store. Use the Desktop composer to launch one short owner turn with one supervised benign child. The owner should wait for the child and end. Inspect only exact callback references and require at least one retained terminal callback with capture status 3 and a missing receipt at that point.
2. **Switch and settle.** Give the same Desktop agent one closeout turn. It selects #458 for future work and launches fresh CLI processes to read status and retry the exact prior child and owner using `session-codex-hook SESSION THREAD ACCOUNT ROLLOUT_ROOT --retry ATTEMPT`. Preserve callback ordering and individual exit codes. Confirm the original two attempts still bind to #461, with an exact native parent/child correlation and one receipt per attempt. The closeout invocation itself belongs to a later turn and may require a subsequent settlement. Report the cutoff and any explicit attribution of extra turns.
3. **Hold and publish.** The agent freezes `session-export-batch SESSION 461` to a private file, checks the two expected roles, and uses `session-publish-batch 461 REPOSITORY BATCH`. Use a no-network, unauthorized-origin checkout for a safe refusal before the live write, preserving the same batch and comparing the protected remote before and after. A returned commit alone is insufficient. Independently fetch planning and compare both mode-100644 paths and exact SHA-256 bytes; scan both identities across all planning story receipt paths. Repeat the same frozen batch once. Verify identical bytes and count, no receipt-path change on replay, and no assignment to #458. Record the actual execution and writer identity. If the chat cannot use the writer directly, verify whether the sanctioned frozen-batch handoff works and record it as assisted.
4. **Verify unresolved attribution.** Use a separate private scratch database for a controlled child with missing owner-start binding and exact retained evidence. Exercise supported status, retry and export. Require unresolved coverage to remain visible, no fabricated story assignment, and an empty export for either story. Where the shipped focused tests already supply suitable isolation, record the exact test and reproduce the control through the CLI whenever possible. This control and the publication refusal have distinct acceptance results.
5. **Deliver.** Record commands with private operands redacted, tool elapsed times, additional model turns, native timing and token splits where available, provider cost versus verified billing, operator actions, replay evidence, and a minimal closeout recommendation. Record a separate verdict for each leg, including any required human action and remaining gap. Restore the disposable store's prior selection. Obtain independent review of the pinned evidence, verify it on remote planning, record retrospective and cost evidence, then reconcile GitHub and Project 24. There is no source PR for this spike.

## Acceptance

| Leg | Pass evidence |
| --- | --- |
| Native capture and delayed settlement | A live composer owner and one supervised child, exact terminal references, at least one pending before native retention, and two exact #461 receipts after switching and opening fresh processes |
| Agent-owned publish and replay | The same disposable chat issues the commands, remote readback verifies both exact bytes once on #461, and replay adds no registration |
| Failure and attribution | Authorized writer refuses a mismatched origin without publication, and the missing-binding control stays pending and unassigned |
| Delivered research | Immutable sanitized evidence, independent review, and an actionable recommendation. Any failed or unrun leg stays explicit and limits the recommendation. |

The smallest viable workflow will distinguish the command task, which may finish in one follow-up turn, from full coverage of that follow-up turn's own post-completion usage.
