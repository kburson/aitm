# Qualify live session-owned Claude Code parent and child accounting

## Outcome

Qualify one live Claude Code foreground Agent parent/child pair through the shipped session-owned effort workflow. Carry forward the native closure and membership evidence from #271 and #204, and the bounded no-double-counting result from #433. Start with one pinned macOS Claude Code route.

## Acceptance

- Use a genuine synchronous foreground Agent invocation with a metered child. Record the platform, Claude Code version, package revision, and launch route. Bind the parent and child to their original story at dispatch from exact native lineage and completion evidence.
- Reconcile the native parent and child request identities and token counters. Count each request once in the story rollup, including when a parent total or Agent result includes child usage. Carry missing or ambiguous lineage and membership as an explicit coverage gap.
- Change the active story and recover in a fresh process. Verify that both receipts retain the original attribution. Publish sanitized receipts to protected planning through the shipped workflow and verify remote readback and that identical replay adds neither receipts nor usage.
- Obtain independent review of the live evidence before adding the exercised provider route to the support matrix. Record any remaining host or route limits.

This story covers the session-owned foreground Agent route. Legacy monitor writer admission, journal replacement and project-write ACK are outside scope. #466 separately covers ordinary Claude CLI turns on Linux.
