The original project, scope, time basis, observed time and keyed session, stream and original span match the saved first owner. The current contender separately proves actual native capture and eligibility on its independently approved physical source. The bounded positive path requires a different independently approved source ID and a distinct actual incarnation from the durable accepted child and a source ID different from the immutable first claim. The approved contender's real source, locator and incarnation are retained. That evidence can attest a conflict and never grant positive v2 succession or owner transfer. An apparent divergence on the original physical source without the second approved carrier stays held.

Require a durable accepted v2 row for the proposed common predecessor. Require distinct normalized typed successor usage from every accepted state of this key inside the transaction, including the first claim, common predecessor, direct accepted child and all later accepted descendants. Matching any accepted usage stays HELD with no conflict row, even if the fingerprint differs due to numbering. Require distinct material and child prefix refs as well. Both actual later ordinals must be greater than the common predecessor ordinal. Neither internal revision numbers, numeric counters, filenames, or an equal material with a changed prefix alone prove a divergent branch. Require the contender to meet #199's same-owner proof and exact common native prefix. The distinct child branch can differ at any authenticated later position after the common predecessor. ## Interfaces

One new private STRICT `content_disputes` table with `key TEXT PRIMARY KEY REFERENCES claims(key)`, `sequence INTEGER NOT NULL REFERENCES commits`, and `payload BLOB NOT NULL`. Use the existing atomic batch sequence and write the parent commit before its child. No update path. The closed private payload is `_ContentDisputePayload(common: SourceRef, accepted: _ContentEdge, contender: _ContentEdge)`. Each closed `_ContentEdge` has exactly `material: SourceRef` (the keyed ref of exact normalized usage), `origin: ClaimEvidence` (source ID, surface, keyed session/stream, original half-open span, capture generation and boundary), `later_ordinal: int`, `prefix_ref: SourceRef`, `locator_ref: SourceRef`, and `incarnation_ref: SourceRef`. Its later half-open span is [later_ordinal, later_ordinal+1). No raw source, paths, account data or redundant contender tokens are stored. Any later disposition must independently re-prove authority. On read, validate the closed typed refs and the immutable owner/original claim. Require the stored common and accepted child to match their durable rows at or before the dispute sequence, including that the child's durable predecessor equals the stored common ref.

Append `JournalView.content_disputes` with default empty to preserve existing construction. Return a separate private `ContentDispute(key: SourceRef, project_id: UUID, common: SourceRef, accepted: _ContentEdge, contender: _ContentEdge, sequence: int)` projection. At as_of return only rows at or before the requested sequence in existing deterministic sequence/key order. Keep current and historical pending claim contents intact alongside separate dispute evidence. M09/M13 later own downstream view effect.
