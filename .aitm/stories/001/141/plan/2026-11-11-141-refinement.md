## Acceptance

| Case | Observable result |
| --- | --- |
| Aliases, relative imports, re-exports and cycles | A test importing an aliased package symbol reaches its initializer and the initializer's relative import owner. Exact directed kinds and the cycle are present. A local from-list submodule and an import across mapped package roots retain both the initializer and applicable module edge. |
| Uncertainty coexisting with known edges | Direct or imported/aliased dynamic loaders and pytest plugin declarations preserve known edges and record their reader and reachable input scope. An ambiguous namespace or module owner retains all possible represented edges and an unresolved record. Trusted bounds are explicit and unbounded readers may reach all applicable packages. |
| Pytest invocation scope | Applicable tests reach ancestor `conftest.py` files through a qualified cutoff and shared config inputs. Nested fixtures do not apply to siblings. A fixture reaches the module it imports. A product invocation can include the CLI test file outside the product directory. An unqualified fixture or config scope, missing required config or unmapped source in scope is visible as uncertainty. |
| Exact snapshot, failure and determinism | A real #140 before/after pair preserves a former dependency for a rename or deletion, uses each endpoint's bytes and produces distinct endpoint identities. Python source encoding and raw path identity survive. Syntax and unsupported modes retain unresolved readers, and a failed bound source read refuses the graph. Repeated graph construction yields equal, sorted and deduplicated records. |
| Verification and delivery | Retain behavior red/green, passing focused and T02/T03 checks, and two-file Ruff check/format evidence. The hosted #103 workflow does not collect the new focused file or include the graph module in its four-helper coverage denominator. Obtain required exact-candidate #103 jobs, owner tree disposition and independent source review for the `tools/ci/` additions. |
