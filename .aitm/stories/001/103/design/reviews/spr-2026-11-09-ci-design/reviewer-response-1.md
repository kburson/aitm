## Required changes

1. **SPR-CI01 · Bind the aggregate success to the producing workflow and run.** Lines 15–17 and 41 currently name `aitm-ci` and record SHA/job outcomes but do not require the closure owner to identify the exact workflow run and attempt that produced it. A same-name status or a conditional skip can appear acceptable to branch protection. Define an exact passing record for the repository, canonical workflow path or workflow ID, PR event and target, run ID/attempt, tested SHA, required lane evidence, and an aggregate job that actually completed with success in that same completed successful run. Explicitly reject a skipped, neutral, cancelled, missing, duplicate/ambiguous or other-workflow aggregate even if the merge UI permits it. Add these cases to gate verification. Keep any enforcement change separately authorized, and bind the expected check source where supported if enforcement is later enabled. [GitHub required check behavior](https://docs.github.com/en/pull-requests/how-tos/merge-and-close-pull-requests/troubleshooting-required-status-checks) · [GitHub protected branch checks and expected sources](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches#require-status-checks-before-merging)
2. **SPR-CI02 · Provide a fresh route when the target or tested inputs move.** Lines 15–19, 41 and 44 require exact head/base evidence, but ordinary PR activity and a push to trunk do not define how to obtain a fresh PR result after the base advances or the PR is retargeted without a head push. A rerun of the old event uses the old SHA and ref. Before Review and again before merge, compare the live declared base and head to the tested pair and hold the gate on drift. Name a safe, ordinary way to produce a fresh PR event on the updated candidate and confirm the two parents of the new test merge. Keep a trunk push check as evidence for its own tree. At refinement verify the trigger and rerun route on the first intended parent, including a representative declared integration target if the design claims support for it. [GitHub pull request events](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#pull_request) · [GitHub rerun identity](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/re-run-workflows-and-jobs)
3. **SPR-CI03 · Preserve the Darwin evidence floor on capability skips.** Line 36 first says an unexercised required case keeps the gate closed, then offers an authorized disposition for the affected capability. An operator could read that as permission to pass a candidate whose required ACL, publication, lease or restart evidence never ran. Distinguish predeclared optional capability skips from missing required evidence. Name the approved hosted runner and environment capabilities at refinement, and require execution of the essential Darwin cases on a qualified runner. A missing required capability or check stays visible as blocked and must not make `aitm-ci` pass. The bootstrap exception in line 19 applies only to the initial Before Develop route preflight. It does not replace the real Actions result, measured coverage, independent review or closure. Add a negative acceptance case for a required Darwin capability being unavailable even if other lanes pass.
