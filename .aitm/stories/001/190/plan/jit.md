## Design

Implement `build_snapshot(tree: PlanningTree, selector: ReportSelector | None = None) -> Snapshot` in `tools/story_dashboard/snapshot.py` and add only `tools/story_dashboard/tests/test_snapshot.py`. A Snapshot is JSON-compatible data with schema `aitm.story-dashboard/v1` and the fixed AITM repository `kburson/aitm`. It records planning commit, commit timestamp, supplied as-of, selected usage report and resolved receipt digests. Story rows are sorted by ID and include title, state, validated ancestry, latest eligible lifecycle progress and its evidence, estimate hours as an exact Decimal string or null and evidenced phase/roles/basis, and the projected timing and usage measures. Use Decimal's canonical string for estimate hours without float conversion or unbounded fixed-point expansion. The projector output supplies the values and scope; A05 serializes them without recomputing totals. Timing units are integer milliseconds and usage is an exact decimal string or null. Each measure retains coverage, basis, independent evidence-through, qualified pending flag where applicable, and safe provenance. Include direct/descendant/inclusive timing and direct/inclusive Cost, contributions with typed scope, distinct elapsed/age scopes, and calibration eligibility and reasons. Preserve Unknown as null with explicit coverage.

For the renderer, top-level keys are `schema`, `repository`, `planning` (commit, committed_at_utc, as_of_utc), `usage_report` (selector, source_sha256, receipt_digests), and `stories`. Each row has `id`, `title`, `state`, `parent`, `descendants`, `last_progress`, `estimate`, `timing`, and `cost`. Timing keys follow #188’s interface. Cost exposes direct and inclusive measures. Preserve phase and role contributions with their story IDs. Only canonical repository-relative story/evidence paths are eligible for commit-pinned GitHub links. Convert a canonical journal source and positive :line into the matching #L anchor. Keep opaque source references inert. Progress uses the latest eligible workflow-state, story graduation, or accepted-document event. Do not use the snapshot clock or a receipt journal write as workflow progress. Validation collects deterministic scoped input, attribution and usage gaps, and binds its record to the snapshot's SHA-256.

The CLI uses `python -m tools.story_dashboard.snapshot --repo PATH --commit SHA --as-of UTC --output DIR [--usage-report SELECTOR_JSON]`. The optional argument names a local JSON file containing A04's selector. Validate the pin and cutoff with A01 and the selector with A04. Reject duplicate selector keys. Resolve output paths physically, including symlinks. Reject output inside any Git worktree, including an unrelated checkout; check physical .git file/directory ancestry, linked worktree discovery and sanitized Git environment for unresolved child destinations. Validate both resolved output leaf targets before writing either, including preexisting symlinks into worktrees. Expose this output-path validation for B01. Serialize both artifacts as sorted compact UTF-8 JSON with a trailing newline. Write each artifact using same-directory temporary bytes and atomic replace. Bind validation to the exact snapshot bytes so an interrupted pair cannot masquerade as a matching report. The command writes only local output, performs no board or receipt writes, and never includes raw private payloads.
