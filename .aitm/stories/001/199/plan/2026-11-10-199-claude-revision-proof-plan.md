## Review focus

- Multiple authentic revisions in one cold read must each bind exact material to its own predecessor, with ordered distinct later spans for successive revisions of the same request. A single terminal row can complete several independent requests with separate predecessor identities and the same later ordinal. A numeric revision or matching request ID alone gives no authority.
- A project or story switch at a later native position may change later requests without moving the original usage project, story, time or interval.
- A shared read can be legal for project B while the original project A has no capture entitlement for the later row or an indivisible cumulative span crosses a disable. Re-enrollment and a new location cannot legalize that update.
- An untimed cost-state row's physical ordinal differs from its preceding timed context and can land outside an allowed interval. A timed result is valid only on the existing successful exact reconciliation path.
- A fixed-prefix copied read may reproduce the logical witness. A copied handle, wrong writer, mixed physical read, changed prefix, unknown incarnation, foreign request, unknown usage or ambiguous overlap must not issue forward authority.
- Preserve all diagnostics and replay obligations byte for byte in this leaf. Quota classification is a separate coverage concern and can never authorize progress while its own replay obligation is unretained.

## Interfaces

The private monitor producer callback receives the actual predecessor Revision, successor Revision and committing SourceFrame or SidebandFrame at the accepted emission. `ProviderAdapter.read_delta(..., _revision_witnesses=None)` accepts an optional private per-call collector. Only the final successful fixed-prefix adapter result appends exact `(NativeObservation, _NativeRevisionWitness)` object pairs to it. Clear the provisional collection before any scope-enrollment rescan. The collector never enters the public four-field AdapterBatch and leaves its serialization unchanged. The normalized witness includes the provider kind, canonical observation key, exact predecessor and successor material fingerprints, original native identity and position, predecessor evidence ordinal, exact later evidence position, and keyed row-prefix witness. Physical locator, incarnation and complete cursor stay in the fixed-read context, separate from the copy-stable proof identity. No raw row or payload crosses the seam.

The source walk and adapter derive the fingerprints with the approved source's `source._ledger` evidence namespace using separate `claude-revision-material` and `claude-revision-prefix` pseudonym namespaces. ScopeState checks this is the approved registry source evidence key, validates the references through `registry.source_evidence()`, and recomputes the material fingerprints from the exact paired predecessor and successor observations of the final fixed read. A missing prior object cannot issue a forward witness. Prefix derivation uses the actual scanner-verified row prefix in the current rechecked fixed read, without disclosing its raw value.

ScopeState copies the collector into a new default-empty, private `VerifiedScopeBatch._revision_witnesses` tuple with `repr=False, compare=False` and keyword construction. It is runtime-only and leaves all public and persisted wire shapes unchanged. `ScopeState.verified_revision(batch: VerifiedScopeBatch, observation: NativeObservation) -> _VerifiedRevision | None` accepts only `self._batches.get(id(batch)) is batch` and the exact observation object from that issued batch. A caller-built batch or collector conveys no authority. The result binds the original scoped owner and time, later capture eligibility and the exact writer and read. Its consumer must use the original proof with the exact batch, confirm current custody again before writing, and match the saved claim's original scope separately. The predecessor material fingerprint is available for that future comparison. No diagnostic classification, claim mutation or cursor release occurs here.
