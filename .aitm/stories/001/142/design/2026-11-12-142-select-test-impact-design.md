# #142 leaf design — Select and explain test impact

[Story](../story.md) · [Accepted #133 design §3](https://github.com/kburson/aitm/blob/2ff1b49ed3a3f91c8164d6c7b0e1dbe4c15cd3f9/.aitm/stories/001/133/design/test-impact-analysis-design.md#L70) · [Accepted T05](https://github.com/kburson/aitm/blob/dbe0d68b3e7b977c9fbf51e26d9ae8c6f629af84/.aitm/stories/001/133/plan/test-impact-analysis-implementation-plan.md#L231)

#142 produces an explainable selection from exact changes and complete test inventories. The same input produces the same selected obligation identities, per-path dispositions and dependency witnesses. This leaf owns `tools/ci/tia/selection.py`, `tools/ci/tia/edges.json`, and `tools/ci/tests/test_tia_selection.py`. T06 owns the local command and execution, later leaves own hosted admission and inventory reconciliation, and #172 owns testmon measurement.

## Exact inputs and result

`select(before: Snapshot, after: Snapshot, inventory: InventoryPair, policy: SelectionPolicy) -> Selection` consumes the two delivered T03 snapshots from one `resolve` result. Require before role `baseline` and after role `pr-tested`, `trunk-tested` or `local-effective` as appropriate to the mode. Verify repository, common baseline, matching change tuples and exact hosted or local provenance. T03 defines both hosted roles. For `trunk-tested` the candidate matches that exact trunk collection tuple, while the before collection still binds its own exact endpoint and independent run evidence. Check every old/new change entry against the corresponding endpoint. A duplicate or contradictory path or binding is unusable. Preserve raw Git paths as bytes and sort them bytewise.

`InventoryPair` carries the original canonical T02 full inventory bytes for each endpoint. Either byte string can be absent. `SelectionPolicy` carries the reviewed T04 provider policy, reviewed declaration bytes, and an independently supplied inventory expectation per endpoint. An expectation supplies the full T02 `SuitePolicy` (suite and #103 policy bytes), expected complete lane identities, and the expected raw inventory SHA-256. The trusted caller establishes the provenance and custody of hosted inventory evidence before calling. A local result retains advisory provenance. Verify the expectation against the original bytes, canonical schema, complete workload and lane set, exact raw policy digests, complete rows and their order, uniqueness and source membership. Reuse delivered T02 policy, scope and obligation projection helpers where applicable.

For hosted input, each expectation also contains the independently known repository, commit, tree, ref, run ID and attempt of the **collection**. Match the candidate expectation to the tested endpoint and the exact `HostedBinding` from T03. Match the before expectation to the exact base commit/tree and its own independently verified protected-target collection ref, run and attempt. The T03 before snapshot carries the candidate's `HostedBinding`, so its run/attempt cannot fill the before collection expectation. Both inventories must match their own complete expectation, including the raw-byte digest. For local input require `local_advisory` and `binding.snapshot.content_digest == snapshot.digest` at each endpoint. The trusted caller supplies the matching local digest and lane expectations. Provider-shaped caller data alone cannot establish hosted proof.

Validate each inventory using its own expected full T02 policy. Distinct before and after policy digests force full selection on an independently validated candidate inventory, with an explicit policy-change reason. The selector never approves that change. Its result binds the two snapshot digests, the two original inventory digests when available, the graph provider policy identity, declaration digest, and both expected suite and #103 policy digests.

`Selection` exposes the input identities, the resulting mode (`selected`, `full`, `no-tests`, or `unavailable`), ordered surviving keys, ordered removed keys, per-path dispositions, policy reasons, and witnesses. The stable obligation key is `(provider, owner, platform_scope, nodeid)`; parameter IDs and platform are part of the key. A witness retains the original changed raw path, the exact surviving test key, ordered graph hops, edge kinds, rule identifiers and the endpoint side. Mandatory and newly collected IDs carry their own reason, including when the selection already reaches them. A local result carries advisory provenance.

Verify the candidate snapshot, collection expectation and full inventory independently before checking pair agreement. If its exact applicable full set cannot be established, return unavailable with no executable selection and preserve every known reason, including a missing required row. If the before inventory independently validates, preserve verified T03 whole-file deletions with their exact before keys, and identify a missing required key in otherwise authenticated candidate bytes as invalid evidence. Neither fact makes the candidate executable. If that set is sound but the before inventory, pair agreement, graph or other impact evidence is incomplete, select its entire full inventory and preserve the reason. A contradictory pair cannot make the before binding effective. Never derive a full result from a partial inventory. Uncertainty may be discovered during graph building, declaration validation, traversal, or inventory reconciliation.

## Graph, declarations and traversal

Build two T04 graphs with the same trusted provider policy. Add the exact reviewed declarations to each graph. Versioned `edges.json` holds rows with `id`, `consumer`, `input`, `kind` and `rationale`, and explicit path classification rules with their IDs and rationale. Paths are exact repository-relative UTF-8 names without dot segments, escapes or globbing. Graph and change identities retain raw paths; an unrepresentable path cannot match a declaration by display spelling. Validate schema and reject duplicates and conflicting rules. A declared edge can cross packages and identify subprocess, fixture or other runtime input. The initial manifest records the existing monitor rate-card JSON dependency in `aitm_usage/pricing.py` and the CLI smoke test's subprocess dependency on the `aitm-usage` console entry point in `aitm_usage/cli.py`. Both rows apply to the exact paths on either side of the comparison and across applicable lanes. No filename similarity supplies an edge. A declaration with a missing or non-regular endpoint introduces uncertainty for a changed path when either declared endpoint is the changed seed or is reached through reverse traversal of valid edges on that side. Retain the declaration rule and affected endpoint in the reason. Missing endpoints unrelated to the seed and its reached paths supply no evidence for that change.

Traverse consumer-to-input edges in reverse from every old and new changed path on its applicable side. For the same modified path, consider both sides. For renames preserve both path identities and recover former consumers from the old graph. Deduplicate nodes while traversing cycles. Choose a shortest witness per changed path, test and side, with stable ordering by raw path, edge kind and rule IDs for ties. Keep distinct side evidence, including a former path whose surviving test also has a current path. Index test module paths from the inventory on the same side as the witness. Join before-side keys against the exact candidate key set before adding a surviving witness. Record missing keys separately as removals. Candidate-side reach selects its own exact collected keys. Newly collected keys always carry their own selection reason. A changed test file supplies a self witness for its surviving candidate IDs. A removed base obligation is recorded even when its path was not among the graph changes. It cannot execute and remains pending inventory disposition downstream. Every removed key forces full when the applicable candidate inventory is available. For a missing required row under unchanged policy, candidate validation yields unavailable. An independently reviewed candidate policy can establish a complete candidate set after removing a formerly mandatory ID. Selection records the removed key and requires full and downstream disposition. Compare complete rows for keys shared by both endpoints. Any same-key metadata or disposition change requires full with the exact changed keys recorded. Keep a T02 allowed-skip row in obligation accounting and witness output. Actual skip eligibility and runtime outcomes remain with the caller's validation route.

Check unresolved graph scope against the changed path and nodes reached on its applicable side. Prefix matching uses whole path components, so a bounded unknown reader that may reach a transitive consumer still introduces uncertainty. An unbounded record may reach the entire applicable suite. A known witness does not resolve a separate unknown scope. Full fallback selects the whole applicable inventory across all qualified lanes and preserves established witnesses and uncertainty reasons.

Every changed path records a resolved consumer, reviewed non-test rule, or explicit uncertainty. A positive exact non-test rule can establish no test impact only in the absence of graph, declaration or unresolved evidence to the contrary. A shared-input rule selects the whole applicable inventory. Global or unclassified configuration and unexplained changed files fall back to full. A no-tests result requires positive policy for every changed path and no mandatory or newly collected obligation. Required cases still run when all changed paths are positively classified as non-test. The current genuine T02 full policy always includes mandatory CLI and child-process obligations, so its docs-only case keeps those IDs. Exercise a no-tests result in a focused decision fixture with no mandatory or new IDs.

## Acceptance and boundaries

- Assert exact former-consumer witnesses for rename and deletion and stable obligation keys across before and after. Check unavailable when a required candidate row is absent under unchanged policy. With independently reviewed endpoint policies that make the candidate inventory complete, record the formerly required key as removed, select full, and require downstream disposition.
- Assert direct, multihop, cross-package declared subprocess/fixture and changed-test witnesses. Exercise duplicate paths, cycles, stable tie-breaking, parameter/platform identities and actual raw path bytes.
- Assert known edge plus unbounded uncertainty triggers the complete multi-lane inventory. Cover relevant and unrelated bounded scopes, missing declaration endpoints, stale/bad inputs, and unavailable result for invalid candidate inventory.
- Assert an arbitrary filename match gives no dependency evidence and a docs-only fixture qualifies for no-tests only with a positive policy rule and no mandatory or new ID.
- Use genuine T02 projection and T03/T04 endpoints in representative integration fixtures. The three new paths are #103 gate controls at the pinned trunk. Run their focused suite locally and the unchanged #103 hosted gate on the exact PR separately. This leaf never schedules tests, grants gate authority or consumes testmon output.
