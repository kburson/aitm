## Acknowledgment, late change and capacity

- [ ] `RoutingJournal.ack(delivery: ProjectDelivery, claim: _DeliveryClaim, receipt: _DeliveryReceipt) -> _DeliveryAck` checks attachment ownership, then rereads the exact immutable destination receipt and effect before opening the journal BEGIN IMMEDIATE. The proof's project key remains physically pinned for the operation and is never passed to the journal. Within BEGIN IMMEDIATE get the service claim key from the typed claim argument and require authenticated exact existing ACK first if this is a historical replay. Otherwise reread exact current committed claim and validate full material and sequence. Check the forward mapping from service claim key to the project-local row key before the project read. Require project UUID, destination key, original claim digest/revision, local row and receipt join. No ACK based on a project pseudonym or candidate label alone. Revalidate pins under the original writer lease before commit. A late change to expected revision or a content dispute before ACK refuses the new ACK; exact prior ACK replays its historical result. No compensating destination write. Unrelated ownership disputes leave the original accepted owner intact. Use canonical typed _DeliveryAck containing exact service claim, verified destination receipt, and ACK commit seq; seal using the journal service key in namespace monitor-delivery-ack-v1. Read exact existing ACK first, authenticate both row and payload, and make an identical retry a no-op. If absent, append exactly one ACK and journal commit. This is an internal publication reference; #122 independently witnesses external publication.
- [ ] Define the accepted tail per (project UUID,destination key) as MAX(claim_sequence) over that destination's verified ACKs, default zero. It is a high-water mark and can have unacknowledged earlier obligations. A later successful ACK advances it. An older still-current receipt may receive a durable ACK and preserves the existing tail. A superseded revision creates no new ACK. Capacity tracks distinct unresolved latest revisions individually and does not infer them from the tail.
