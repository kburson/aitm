A batch can store several ordered edges for one key at one commit sequence. Latest view uses `(sequence, later_ordinal)` order and prior view at an earlier sequence sees only the prior material.

Use its `position` or `observed.checkpoint.cursor`, match the current native source/locator/incarnation tuple, and reauthenticate the historical epoch prefix with `_capture_position(..., fixed=historical_cursor)`. When a v2 durable head exists, additionally obtain the fresh predecessor's issued witness, and require that its exact later ordinal and copy-stable row prefix equal the durable head's. The delivered prefix_ref is a service-keyed fingerprint of the scanner SHA-256 over every raw byte from file start through the actual committing row, including the complete row terminator.
