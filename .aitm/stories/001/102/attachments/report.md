# Linux usage provider compatibility spike

November 9, 2026 (America/Chicago) · [Spike #102](https://github.com/kburson/aitm/issues/102) · [Monitor follow-on #100](https://github.com/kburson/aitm/issues/100)

## Result

All three exact pinned provider binaries started and exposed usage or lifecycle interfaces in an unprivileged arm64 Linux container. The #83 collector itself fails at its private-path and publication boundaries on Linux. Linux has workable primitives for an equivalent host adapter on the tested local filesystem. This evidence is sufficient to choose design boundaries and plan separate qualification. Authenticated model turns, Linux-native project marker proof and a real systemd user-service lifecycle remain release gates.

## Environment and evidence boundaries

Docker Desktop Linux engine 29.7.2, Debian GNU/Linux 12 (bookworm), kernel `7.0.12-linuxkit`, aarch64, CPython 3.13.18 and an unprivileged container UID. The Python image was selected by manifest digest `sha256:a5a7017efc5969e00ae2b91c8eb0631049a569652aa4ffc4501769049ae45c72`. All execution probes ran with network disabled, capabilities dropped and disposable provider homes. No provider credentials, host provider homes, or real transcripts were mounted. Source inspection and stock collector probes used protected release `f80f22645e2008c4cac9dc6e4003640bba976b5f`. No modifications were made to the collector.

The provider runs below show executable availability and advertised or generated interfaces. File and process tests used synthetic data. No result in this report is a live model usage sample or an end-to-end collector qualification.

## Collector port findings

| Boundary | Observed evidence | Implication for #100 |
| --- | --- | --- |
| Private paths and ACLs | Stock initialization stopped at an unregistered numeric UID. Direct validation returned `Private ACL validation requires macOS`. The stock guard selects the Darwin account home layout. An FD-relative `O_NOFOLLOW` open rejected a symlink with `ELOOP`. A mode-0700 directory retained an independent POSIX default ACL, and a child created with permissive mode inherited an access ACL. FD-based xattr reads distinguished absent and present access/default ACLs. | Preserve canonical trusted owner, mode, inode, ancestry and single-link checks. Give Linux explicit access and default ACL validation and fail closed when enforcement cannot be established. Resolve a stable per-user guard location independent of per-process HOME/XDG overrides, preserving the same guard across manual invocation, service execution and cutover. Test named users, permissive defaults, symlinks, and unsupported filesystems. |
| Atomic publication | Stock resolution returned `Exclusive inbox publication is unavailable` on Linux. The Darwin primitive is shared by inbox files and staged export directories. Linux FD-relative `renameat2(RENAME_NOREPLACE)` published a file and a directory on the tested filesystem. An occupied destination returned `EEXIST` and preserved source and destination identity. Directory fsync succeeded. | Implement no-replace publication for both entry types while preserving collision replay, pinned directory checks and source/destination durability ordering. Do not silently fall back to replacement when the filesystem or syscall cannot prove exclusivity. Test local supported filesystems and declare unsupported filesystems explicitly. |
| Writer guard and SQLite | Competing processes could not acquire an exclusive nonblocking `flock` on a file or directory while held. Each lease was reacquired after the holder was killed. SQLite WAL mode preserved a committed row across a reader process. | Keep one guarded writer per project and the inbox lock. These are primitive observations. Journal reservation, project-commit/ACK crash recovery and cutover still require integration tests. |
| Wake and reconciliation | inotify delivered append and rename-in events. A root directory watch missed a nested write until that directory received its own watch. A synthetic burst exceeded the 16,384-event queue limit and produced `IN_Q_OVERFLOW`. | Implement one logical watch set per source root, with recursive directory coverage, dynamic watch enrollment and bounded metadata-first rescan after overflow or watch loss. Changes wake a stream. Verified source identity, cursor continuity and ownership decide what enters the ledger. |
| Service lifecycle | Container PID 1 was a shell and there was no systemd user bus. Linux exposed `/proc` process start ticks and `pidfd_open`. #83's actual activation code inspects a macOS GUI LaunchAgent and uses Darwin libproc. | Use a Linux service-manager adapter and independently bind readiness to the loaded unit, same-user process incarnation, executable/runtime and a fresh matching collector heartbeat. Test on a real supported systemd user session. Document when an enabled service starts, how logout behaves, and whether headless persistence needs an explicit lingering policy. Keep no-bus and restricted hosts distinguishable from service success. |

## Design and planning handoff

1. Separate provider surface qualification from the OS supervisor, secure filesystem, process identity and watch boundaries. Reuse provider-neutral normalization, routing and reporting. Capability declarations should include actual host surface and format, native scope-proof granularity and coverage limits.
2. Carry Codex CLI marker compatibility as its own proof. Retain the exact Linux carrier and adjoining request sequence. Treat an absent or unproven marker as unattributed or held, according to whether project ownership is proven.
3. Use a Linux environment with a real systemd user manager for install, unattended restart, stop, process/heartbeat identity, crash replay, restore and rollback proofs. On approved Linux client accounts, collect synthetic tasks through each supported real provider. Verify wake/park/resume, verified project and story boundaries, matching usage, continuity across restart, and coverage when records or hooks are absent. A release claim for another architecture or filesystem requires its own evidence.
4. Keep credential-free CLI, adapter fixtures and Linux primitive probes as repeatable CI checks. Keep native authenticated-provider and service-lifecycle qualification as a separate gate, with sanitized receipts and raw evidence retained privately.

The deliverable is this research report. The probe scripts and synthetic data are disposable.
