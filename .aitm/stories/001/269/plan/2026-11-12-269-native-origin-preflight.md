# #269 native origin preflight

Two disposable macOS Claude Code 2.1.318 sessions each enrolled the parent with the existing writer before Agent dispatch. The scratch launcher polled approved-root file metadata and the new child transcript while the coordinator lease was held. Both first complete snapshots contained 10 child rows and no metered assistant response. The final file preserved the exact observed inode and byte prefix. Both runs used a structured scratch startup hook for the existing scanner recognizer. Neither used child lifecycle hooks. The replay checks joined the native parent, child and sidecar metadata without consuming stream stdout.

The registered checkout matched every scanner frame inside the parent prompt-to-result and child-origin intervals. Native bookkeeping rows without checkout context remain separately unanchored; they are not treated as ownership evidence. The existing registry found the parent's full prompt-to-result span eligible. The current scope API refused both files after sidecar discovery because the session stream was ambiguous. Nested refs passed the service namespace check but had no enabled capture epoch. Reopen reproduced these outcomes from the saved scratch registry. No child epoch, covering route or journal claim was issued.

A separate copy in a scratch root confirmed ordinary refusal when the copied sidecar shared the parent's stream identity. A same-size mutation of an already authenticated parent prefix refused. Any follow-on authority implementation requires its own reviewed design under the existing capture gates. The #204 → #119 edge stays in force.
