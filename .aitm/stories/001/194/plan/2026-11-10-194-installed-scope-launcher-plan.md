## Contract

The existing [#103 observation](../../103/attachments/delivery-evidence.md#agent-measurement) identified that the installed `/usr/bin/env -i` launcher drops the candidate Codex thread before `scope mark` or `development bind` can check the invoking session. Keep `env -i`, the fixed environment entries and Python isolation flags. Only when the incoming variable is set, add exactly one quoted `CODEX_THREAD_ID=value` assignment before the pinned Python executable. Preserve set-but-empty as different from unset. Use the shell's quoted `${CODEX_THREAD_ID+"CODEX_THREAD_ID=$CODEX_THREAD_ID"}` expansion outside the static `shlex.join` arguments. Treat all characters as data. An invoking candidate is transient and only the existing CLI comparison with the authenticated project/session marker authorizes a legacy command.

Preserve the old generator's exact bytes. Keep the existing runtime receipt wire schema and `console_sha256` field. Derive the deterministic old and new launcher bytes using the same pinned interpreter and site paths. Select the one whose SHA-256 equals the existing receipt, then require the complete installed launcher to equal that exact generated byte string. Do not try the other variant after selection. Reject an unknown hash even if it matches the actual mutated launcher. The existing private file, package tree, interpreter, service and schema checks stay intact. On the read path, first check the private receipt and exact schema, wheel custody and the installed executable hash. Check the pinned interpreter SHA-256 before executing that interpreter for version or any probe. Only then derive the site path, select the variant and compare the full launcher. Unknown, opposite and altered launcher bytes all refuse. A fresh prepared runtime pins the new launcher. An existing runtime with a valid old receipt can be read and reused. An upgrade prepares a new pinned runtime from a different approved wheel digest and preserves existing failure or rollback handling. There are two generator call sites. `_prepare` writes and pins the exact new launcher in `console_sha256`, then hands those bytes to `_probe_runtime`. `_read_runtime` checks the pinned digest and selects exact generated old or new bytes before its call to `_probe_runtime`. `_probe_runtime` passes those selected bytes into `_inspect_surface`, which verifies the full installed wheel and runtime tree. No verification site may regenerate the default launcher after selection. Existing `_runtime_for` callers continue through `_read_runtime`.
