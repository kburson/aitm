## Leaf design

### Native position and permission

Use one immutable `ScopePosition` containing qualified surface, source ID, logical session and stream references and native ordinal. For Codex and Claude project the position from the adapter's existing `SourceBoundary`. For Grok expose the sanitized completion position from the existing `GrokCompletion` alongside each `NativeObservation`. The unmarked verified completion keeps its observation key and native position but has no marker receipt. A Grok marker joins only the corresponding qualified prompt and completion using the existing M05 authenticated hook verifier. Do not derive a boundary from a session aggregate, hook arrival, clock time, checkout string or caller-created evidence. Retain Grok completion-time reporting and existing pricing or dispute behavior.

The scope writer creates `VerifiedScopeBatch` and `VerifiedScopeBoundary` only from an approved adapter reading the exact revalidated locator under the coordinator lease. For M04 invoke the delivered reader. For M05 bind the qualified Grok reader, origin and receipt verifier as a writer-owned capability; the M11 coordinator supplies the real service integration. Public typed inputs and valid individual source references cannot mint or replay a scope proof. Expose a short-lived verified observation projection inside `ScopeView`, keyed by exact observation and revision, with source ID, native position, original span, approved anchor match and matching capture disposition. `resolve_route` consumes only that projection and the immutable scope state. Native source identity and anchor matching are revalidated before minting. Scope proof cannot change capture permission. M11 supplies exact discovery, scoped reads and real Grok enrollment. M06 currently has no Grok enrollment bridge. M07 verifies Grok native marker and unmarked completion position with actual M05 fixtures, and returns a coverage hold when capture proof is missing. It must not fabricate a Grok capture epoch or claim activation.

The delivered Codex and Claude neutral recognizers currently accept only legacy mark and bind. Extend neutral recognition narrowly for the installed `monitor scope mark|handoff|dispose --request FILE --json` grammar, with optional `--request-id UUID` exactly where argparse accepts it. Reuse the existing serialized queued UUID receipt output and parent tool-result linkage. Preserve legacy recognizers and reject ambiguous shell or forged output. Consume the existing M04 receipt-linked target once; do not shift to a second request. For Grok, a mark can attach to the same prompt completion whose authenticated hook carried it. A handoff requires independent proof of the next supported turn after the receipt position in the same verified stream. A same-prompt marker alone cannot establish that later handoff. If M05 supplies only the same-prompt link, keep the handoff in bounded proof hold for M11. No destination usage writer or collection starts here.

Resolve a project's anchor only from the adapter's service-keyed checkout context matched to the revalidated registered physical anchor. A unique approved anchor can qualify the project alone, with story Unattributed. A valid ordinary verified scope can supply project proof where anchor context is absent. If the ordinary scope disagrees with a different verified anchor, hold the affected native span for both. Scope explicitly marked project-wide remains distinct from Unattributed. A failed authority check cannot create a conflict against an otherwise valid route.

### Handoff state and hold custody

Create `monitor_scope.py` with `resolve_route(observation: NativeObservation, registry: RegistryView, scopes: ScopeView) -> RouteDecision` and `ScopeState.apply_handoff(command: Handoff, receipt: VerifiedScopeBoundary) -> HandoffDisposition`. Use a separately versioned private scope snapshot under the existing coordinator lease and durable publication. Preserve the M06 registry schema and older control envelope bytes. Store only qualified IDs, keyed native positions and receipt identities, native affected span and decision generations, provenance and UTC expiry. Exact command retries retain their original receipt or disposition. The scope view is read-only without the writer lease.

An authenticated handoff names current project, destination project, target scope and expected generation immediately before its target boundary. A unique anchor alone initializes generation zero. Use the first verified supported request or turn strictly after the serialized receipt in the same native stream. Qualify the destination project and capture permission before enrollment. Preserve the previously verified physical checkout as an explicit stale lineage when it is still unchanged. A→B→C while the session retains A names current B and proves the same retained A context before routing C. For Develop, separately open the destination's exact registered physical worktree, verify its persisted inode and destination project's authenticated DevelopmentBinding from the pinned destination ledger, and join the same owner, attempt and generation to the proposal. The stale A context never stands in for B worktree proof. An unproven checkout change, a prior-generation proposal targeting a later position, or a missing destination owner witness fails closed. Keep attribution and physical checkout distinct. Reuse the existing scope owner compatibility checks in `scopes.py` where they preserve the legacy rules.

Keep the timeline ordered by verified native position. Group competing proposals by the canonical source, session/stream and native ordinal plus before-generation, never by command-derived receipt or boundary references. Reproject the affected suffix when an earlier native transition arrives late; stale later before-generations become held. Evaluate independently valid commands for the same target generation and boundary against the same before-position state. Distinct accepted receipts conflict regardless of delivery order. Return the bounded affected original observation keys and span for later reconciliation. Exact retries have one effect. Only independently verified evidence can resolve or supersede a conflicted span. A later marker does not rewrite already completed requests. M09 and M13 retain the post-ACK and published-snapshot transition.

Use a typed proof hold with immutable first-seen UTC expiry, keyed by project/source/stream and affected ordinal range, bounded to 256 unresolved entries per scope state and a 15-minute initial hold. Replays cannot extend the first expiry. An explicit `dispose` requires registered authority and matching independent native evidence. Release to the prior scope only when continuity and absence of another competing claim prove it. Expired, unprovable, or overflowed holds become explicit provenance-only coverage gaps and never release usage. Persist expiry and disposition under the coordinator. Inject a trusted UTC clock for testability.

### Proposal admission and installed compatibility

Extend the existing typed M06 inbox envelope union with versioned scope, handoff, disposition and legacy compatibility proposals. Use a separate private scope authority snapshot keyed by immutable project and principal. `ScopeState.install_authority` provisions owner-authorized grants under the same registry coordinator lease, from pinned owner-only local configuration and an existing project registration. A local operator is the authenticated owner of the private registered project state. An integration must present its installed private grant scoped to project and permitted action. No proposed grant or path supplied in a queue payload can register itself. A lease-free pinned read of the existing private authority and initialized source key supports producer verification and translation while the writer lease is held. The CLI cannot create those keys or acquire the writer lease. Seal the canonical proposal, authority, project, action and stable command ID before queue publication with a distinct service-key namespace. Existing control envelopes and receipt bytes remain unchanged.

The M06 drain leaves scope envelopes intact. An enqueue receipt reports queued while native proof is pending. M07 keeps the command and its public ID in the inbox, even when the private scope state records a verified disposition. M11 owns terminal publication and retirement. Its narrow handshake writes the exact terminal receipt and command digest to the Registry-visible status path durably before deleting exact queue bytes, so status and retry remain stable. Test that scope application is idempotent and cannot make the queued ID disappear in M07. Test the seam with one consuming fixture; do not start a service.

Add `monitor scope mark|handoff|dispose --request FILE` through the existing private config and exact receipt output route. Preserve raw identifiers as transient input only. For adopted state, route the existing `scope mark`, `development bind`, `scope correct`, `item alias` and `item parent` grammars into the compatibility envelope. Resolve the adopted identity and validate the original ledger command under its existing identity and keyed reference checks. Preserve exact marker and binding receipt UUID and JSON shape. Translate native receipt and session joins only after the original command and invoking provider session authenticate. Relationship commands keep their existing local authority and need no synthetic provider boundary. Scope corrections keep the existing versioned evidence requirement.

Choose the adopted route before `remember_claude_session` or any other legacy write. A pre-adoption producer rechecks under the existing legacy inbox publication lock, so M16 cannot freeze ingress between the authority check and the old enqueue. If adoption won, leave the legacy inbox untouched and publish only through the monitor path after releasing its old lock. Test the check at the admission race. An adopted producer requires a private consumer admission witness bound to project, adopted ledger identity, supported envelope and a verified compatible monitor consumer. M07 defines the gate and proves it with the real compatible inbox reader in an isolated fixture; M11 provisions its reader and M16 installs admission at the reviewed custody cutover. If the witness is absent, fail with a sanitized unavailable result and no queued acknowledgement. M16 owns freeze, transfer and rehearsal of old pending commands. Before adoption, preserve the existing paths and output.

The [#103 installed measurement](../../103/attachments/delivery-evidence.md#agent-measurement) proved that the installed launcher strips `CODEX_THREAD_ID` before the legacy CLI authenticates it. Update the generated launcher in `install.py` to preserve only this quoted invocation candidate across the existing clean environment. The existing session-to-marker keyed comparison and later native receipt verification still decide authority. Preserve exact verification of the legacy launcher variant for previously installed runtime receipts. Recognize only the two generated byte variants, checking the recorded digest, interpreter, pinned directory, wheel and all existing isolated-runtime restrictions. Test the real generated launcher invoking the existing grammar in an isolated installed fixture and a mismatched/missing thread, shell metacharacters and an unrelated environment variable. This is repository implementation and fixture validation.
