# Grok Build CLI usage and scope evidence

**Spike #101 · Follow-on #100 · 2026-11-09 (America/Chicago)**

**Disposition.** The controlled live spike verified two distinct synthetic draft scopes in one Grok Build CLI session across process exit and explicit resume. Native completion and persisted usage matched on both turns. The spike establishes a feasible whole-turn route on the observed macOS build. Production admission, rate equivalence and broader release qualification require separate evidence.

## Probe and evidence boundary

The first attempt used the installed stable macOS arm64 Grok Build 1.0.34, build `3736acbc8658`. Its executable SHA-256 was `9cd26b579840f0f5c9148a8059ad651904c08b41b7f2ef0b4ec04b9ba898844e`. The executable exposes headless JSON and streaming JSON, session creation with a chosen UUID, explicit resume and `grok usage <session-id> [turn]`. The controlled command used a fresh session identity, an isolated unregistered workspace, a private leader socket, disabled compatible hooks and tools, and the existing subscription sign-in. The CLI exited before inference after the provider rejected the cached subscription refresh with OAuth `invalid_grant`. That attempt made no model request. The owner then reauthenticated and authorized the controlled retry. [Grok headless mode](https://docs.x.ai/build/cli/headless-scripting) · [Grok authentication](https://github.com/xai-org/grok-build/blob/2bdd1d6a6369de0e8c68132ea4539e9abd9e14a8/crates/codegen/xai-grok-pager/docs/user-guide/02-authentication.md)

The retained comparison used the 25 most recently modified local `usage.json` files at sampling time and their paired `updates.jsonl` metadata. The analysis compared allowed IDs and numerical fields in memory and published aggregate counts only. Historical provider build, auth mode and invoice association were unavailable for those files. The sample is convenience evidence about observed records, with no claim about all host surfaces or release compatibility.

## Controlled live evidence after reauthentication

The retry used macOS arm64 stable Grok Build **1.0.77** (build `50ca579fa996`, executable SHA-256 `197c66a63e5ac46e07450b0ca21d141ce665050a412180f185dadfae1c7a5b2a`). The installed build changed between attempts, so the proof is pinned to 1.0.77. The retry used the signed-in subscription and no API key. Probe hooks lived only in the disposable unregistered workspace. A process-scoped folder-trust override allowed those scratch hooks without writing a persistent trust grant. Compatible Claude and Cursor hooks, web search and model tool execution were disabled. The two one-turn invocations exited successfully, with an explicit `--resume` of the same native session on the second invocation.

- Before each invocation a disposable controller selected one synthetic draft scope. Each invocation emitted exactly one prompt-scoped `UserPromptSubmit` and one prompt-scoped `Stop`. Each pair matched one durable native `turn_completed` by the exact native session and prompt IDs. The two prompt IDs were distinct. Native execution order was prompt hook, stop hook, then completion in both turns. The first local start receipt identified `new` and the resumed receipt identified `load`. Session shutdown also emitted unscoped `Stop` and `SessionEnd` signals. The scope names came from the probe controller, while the join and order came from Grok. This exercises the native join, with production project and story authorization outside the spike.
- After the first process exited, `grok usage` showed one persisted turn. After the second exited, it showed two. The first turn was unchanged as a JSON value. Selecting each turn independently returned the corresponding row, and two repeated full reads were byte-identical. The CLI matched the native snapshot and both durable completion payloads matched on token counts, model breakdown and cost ticks. Two reads of the native completion stream yielded the same two canonical identities in the probe. This is input replay evidence, with production ledger idempotency still to be tested.

Both observed turns used `grok-4.7-build`, made one model call and reported zero cache creation. The headless terminal records reproduced the persisted cost ticks and their USD conversion ($0.00715836 and $0.00714068). They did not establish invoiced spend, subscription debit or a rate card for `grok-4.7-build`. The published API price card names `grok-4.7`. ## Retained native evidence

| Check | Observed result |
| --- | --- |
| Session identity | All 25 usage snapshots named the same native session as their directory. All compared completion envelopes named the corresponding snapshot session. |
| Turn identity and provenance | 41 stored turns corresponded in source order to 41 native `turn_completed` updates. Each completion carried a nonempty `prompt_id` unique within its sampled session. All 41 matched their corresponding snapshot row on input, output, cache read, cache creation, reasoning and total tokens, cost ticks and model-call count. |
| Lifecycle join | 30 of 41 completions matched a retained `user_prompt_submit` hook execution on the same native prompt ID. 13 matched a prompt-scoped `stop` hook. The sampled stream also contained unscoped `stop` records. Treat hook delivery as incomplete and distinguish per-turn from session-level events. |
| Resume and parking | Six sampled sessions had multiple retained session-start hook execution records, and five had multiple completed prompt IDs. The session-start execution summaries contain the event name and hook run statuses. They omit the start reason. These are observations of repeated starts, with no verified causal park and resume sequence. |
| Token semantics | In all 41 rows with nonzero cached reads, the persisted camelCase total equaled input plus output. Thus persisted `inputTokens` includes cache. Subtract validated cache categories before pricing uncached input. The documented headless snake_case result uses uncached input instead. Reasoning is a separate reported category whose inclusion must be normalized according to the versioned surface. |
| Cost evidence | All 41 sampled historical rows carried positive provider-reported integer cost ticks. A tick value is a provider-reported amount with an unknown billing and rate basis for these samples. Preserve it separately from the common API-equivalent estimate. The headless contract permits missing or partial cost, particularly for subscription paths. |

The stored snapshot is a turn ledger with model breakdown, token categories, completion time, turn number and optional cost fields. The retained native completion update also provides the prompt ID and its usage payload. The provider's public implementation corroborates that the snapshot turn number is presentation order. It can fold updates into a prior turn, reassign colliding ordinals and trim retained turns. Session totals may include inherited history. One canonical observation therefore needs verified provider, session and prompt lineage, with fork, rewind and revision handling. Do not use turn number, wall-clock proximity or matching token totals as the observation identity. ## Consequences for the spec and plan

- Start with a whole-turn observation, keyed privately by provider, native session and verified prompt lineage. Use the native completion as the candidate evidence source and the persisted usage snapshot or usage command as a reconciliation surface. The same observation on both surfaces must settle once. Validate exact version, session continuity, completion shape and token invariants. If evidence is lost, contradictory or partial, preserve the explicit gap. Qualify inherited, rewound and copied histories before admitting overlapping usage.
- A story binding can associate a trusted, pre-authorized scope marker with the next native prompt through a prompt-scoped hook receipt. The live probe verified this join with synthetic scopes. Admit attribution only after the durable native completion proves the same session and prompt lineage. Duplicate hook routes coalesce. An ordinary session wake or unscoped stop never changes ownership or creates a charge. If the monitored build cannot prove a link, retain eligible usage at project level without a story. Treat any aggregate that spans conflicting projects as unallocated.
- Restrict the accounting decoder to the allowed metadata fields and skip prompt, response, tool and hook-output payloads. Watching a changed stream can wake incremental reads. It does not authorize transcription or add costs. Parse each surface under its own schema, especially the full versus uncached input distinction. Avoid double charging aggregate usage and independent subagents until the build's folding semantics are qualified.
- Carry the two-turn probe into release qualification under the real admission path on each supported OS. Qualify hook-disabled collection, concurrent prompts, cancellation, late writes, nested calls, and copied, forked or rewound history. Treat overlapping ancestry as an explicit gap until a verified lineage resolves it. The live spike demonstrated feasibility on one pinned build and leaves the broader three-provider release matrix open.
