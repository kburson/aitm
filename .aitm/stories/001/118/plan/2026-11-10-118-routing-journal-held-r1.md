## Claim and progress proof

Preserve `RoutingJournal.reserve(candidate: RoutedRevision, progress: StreamCursor) -> ClaimDisposition`. A journal-owned preparation method reads through the exact writer's `ScopeState.read_source` and `ScopeState.view(batch)`, and issues transient immutable candidate and batch handles. A caller-constructed `RoutedRevision`, copied handle, wrong journal/writer or manually supplied cursor has no authority. Bind the exact observation object, normalized typed usage and attribution, service-keyed logical observation key, source identity, current route, scope proof and same-read cursor to the handle. Recheck current scope and registry and the pinned physical batch before a write. Use the original adapter key, which already represents the verified native lineage rather than the transcript path. Exact copies and archive transport do not generate another canonical key. Persist normalized usage and scope separately from the transport checkpoint. Hold unsupported evidence rather than synthesizing a route or cursor.

A verified first observation reserves one immutable project owner and writes its normalized pending revision. Exact same-owner content is idempotent. Competing project or different content under that key records one exact deduplicated dispute without changing the original owner or adding another pending charge. An exact prior revision or already committed dispute is replay-safe. A higher integer or changed token count is insufficient evidence of succession. M08a safely holds potential late revisions; M08b supplies provider causal proof and disposition semantics. A first reservation needs the real provider's first verified representation, and later same-batch versions cannot be substituted for it. M08a never counts Grok without an admitted capture proof.

Persist cursors independently by keyed source, surface, stream, locator and incarnation. Use journal-known exact prior progress for that physical stream when preparing the read. Compare the same expected prior inside the write transaction, authenticate prefix continuity with the existing source reader, allow exact idempotence or genuine forward progress and refuse rewind or mismatch. A verified copy can deduplicate a logical observation without replacing the original physical cursor. Never infer continuity across different physical incarnations.

A native batch has one terminal cursor for all its observations. The singular reserve may advance it only if its verified candidate is the complete batch obligation. Add an internal atomic batch entry that validates and stages all obligations from the exact same read and its expected prior cursor. A singular call for a multi-observation batch can stage a private claim with the previous cursor retained. A batch with held, unassigned, unknown, unsupported or competing evidence leaves the earlier cursor replayable. Do not use a journal cursor to make held evidence disappear. For M08a, progress advances only if every covered obligation is represented by a verified claim or exact existing eligible replay and there is no unresolved gap. A full verification failure or injected error rolls back the journal sequence, pending data and cursor together. Staged payload and claim rows never imply a destination write or publication.
