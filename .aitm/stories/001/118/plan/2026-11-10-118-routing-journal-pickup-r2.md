Attach `RoutingJournal` to the exact live `Registry.writer()` and same writer-owned `ScopeState`. Use the existing per-account coordinator lease, with no independent journal lease and no lease acquisition by a producer. The private journal is beneath the pinned registry root and separate from `coordinator.lock` and the initialized service key. Refuse a missing, changed or uninitialized key. Require `registry.view().source_key_id` to be present and equal to the expected store identity before calling the existing `source_evidence()` read path. That prerequisite prevents both key generation and adoption of an unrecorded key. A store reopened by another writer requires the same service key and exact supported schema identity. Invalidate the writer object's lease token on context exit so OS reuse of the same descriptor for a new writer cannot revive an old instance. ## Claim and progress proof

Preserve `RoutingJournal.reserve(candidate: RoutedRevision, progress: StreamCursor) -> ClaimDisposition`. A journal-owned preparation method reads through the exact writer's `ScopeState.read_source` and `ScopeState.view(batch)`, and issues transient immutable candidate and batch handles. A caller-constructed `RoutedRevision`, copied handle, wrong journal/writer or manually supplied cursor has no authority. Bind the exact observation object, normalized typed usage and attribution, service-keyed logical observation key, source identity, current route, scope proof and same-read cursor to the handle. Issue a fresh `ScopeState.view(batch)` at write time under the owning writer and resolve the exact observation again. Recheck current scope, registry and the pinned physical batch. Never rely on a saved preparation view as write authority. Use the original adapter key, which already represents the verified native lineage rather than the transcript path. Exact copies and archive transport do not generate another canonical key. Persist normalized usage and scope separately from the transport checkpoint. Hold unsupported evidence rather than synthesizing a route or cursor.

A verified first observation reserves one immutable project owner and writes its normalized pending revision. Exact same-owner content is idempotent. A verified competing project under that key records one exact deduplicated ownership dispute without changing the first owner or adding another pending charge. Same-owner changed material returns a hold, preserves the earlier cursor and pending bytes, and never creates a durable conflict decision in M08a. Exact existing content or an already recorded ownership dispute is replay-safe. A higher integer or changed token count is insufficient evidence of succession. M08a safely holds potential late revisions; M08b supplies provider causal proof and disposition semantics. A first reservation needs the real provider's first verified representation, and later same-batch versions cannot be substituted for it. M08a never counts Grok without an admitted capture proof. Store service-keyed source, surface, session and stream, exact half-open native start and end, and capture epoch generation and boundary reference for the first owning project. Derive the epoch from the writer's current authenticated registry and the same capture eligibility used by `ScopeState`. These stable fields let the successor find all span-overlapping claims. Keep normalized source usage and verified project scope distinct from physical cursor and keyed route metadata.

Persist cursors independently by keyed source, surface, stream, locator and incarnation. Use journal-known exact prior progress for that physical stream when preparing the read and bind that prior cursor to the issued handle. The current `ScopeState.read_source(source_id, locator, cursor=prior)` verifies the prior physical prefix with `_capture_position(..., fixed=prior.checkpoint.cursor)`, then cold-reads the approved native prefix rather than advancing from an in-memory registry frontier. On reopen, read the exact prior from the journal and prove the replayable suffix through this seam. The batch's `cursor` is the end checkpoint from the underlying adapter, not a starting cursor. If it is absent, refuse reservation and progress rather than inventing a value. Compare the same expected prior inside the write transaction, authenticate prefix continuity with the existing source reader, allow exact idempotence or genuine forward progress and refuse rewind or mismatch. A verified copy can deduplicate a logical observation without replacing the original physical cursor. Never infer continuity across different physical incarnations.

A native batch has one terminal cursor for all its observations. The singular reserve may advance it only if its verified candidate is the complete batch obligation. Add an internal atomic batch entry that validates and stages all obligations from the exact same read and its expected prior cursor. A singular call for a multi-observation batch can stage a private claim with the previous cursor retained. The full batch also includes native boundaries and diagnostics. Keep the adapter's existing typed diagnostics in `VerifiedScopeBatch` so omission or uncertainty cannot look like complete settlement. A receipt-linked scope boundary is an obligation even if no usage follows it. Before moving the cursor, match every such boundary to an exact durable ScopeState event or owned hold for the same keyed receipt and native position. Non-receipt provider boundaries are structural evidence of the read and create no scope command. An unmatched receipt, unresolved hold, diagnostic gap, missing proof, unknown/unassigned route, competing owner or changed same-owner content leaves the previous cursor replayable. A known excluded span can be skipped without writing its usage only when the verified read proves it is excluded for all registered projects. Otherwise do not advance. A complete fixture must prove both journal staging and receipt-bearing batch settlement. A full verification failure or injected error rolls back the journal sequence, pending data and cursor together. Staged payload and claim rows never imply a destination write or publication.
