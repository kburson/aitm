## Grant and reader admission

Use a narrow `scope_admission.py` with typed requests and private sealed authority. An owner-authorized coordinator writer provisions a scoped grant for one registered project, current pinned project directory and ledger key, permitted route and operation. Keep at most one eligible legacy grant for an adopted ledger. An explicit request selects a public opaque grant UUID. The private credential is loaded only by a pinned, lease-free read of already initialized authority and never comes from a repository, a provider transcript, an untrusted environment variable or a request file. Grant and witness records live in private scope admission state separate from the M06 registry schema. Existing registry snapshots and their wire bytes are unchanged. Issuance and compatible-reader advertisement require the coordinator lease. No CLI command can issue a grant, generate a key or install a reader.

Use separate domain tags for grants, reader witness and command seal. Derive the grant secret for the selected generation from existing initialized private authority and give the producer only the scoped credential. Bind witness authentication to grant and protocol, project, physical registry and project identity, ledger key, adopted identity for the compatibility route, an actual verified reader capability, and a bounded validity window. Use UTC, at most 60 seconds of validity and at most five seconds of future issue skew. Witness issuance accepts a transient, writer-instance-bound capability that only the actual typed inbox reader can issue after decoding and verifying a sealed probe envelope under the coordinator lease. The probe does not enter the production inbox. Tests attempt issuance with fabricated and foreign-writer capabilities, then exercise the exact signed scope publication through that same typed reader. A bare registry version, a pid, a public path or a static configuration flag supplies no witness. This is a same-account process correctness gate under the accepted OS trust model. The producer checks grant and witness under the existing monitor publication lock immediately before acknowledging any queue operation. Witness renewal and revocation, grant revocation, rebind and rotation, and any supported update to a bound project or adopted identity take the locks in coordinator-lease then monitor-publication order. M06 already refuses a registered directory rebind. M16 must use the same ordering or invalidate admission under the monitor publication lock before changing custody. The producer holds pinned physical identities through publication and refuses any observed substitution. Test revocation winning between preliminary selection and the monitor-locked grant check. Short expiry prevents a stopped compatible reader leaving indefinite admission; the later coordinator supplies the live capability and renewal. A missing, invalid, stale, revoked or mismatched witness returns a sanitized unavailable result, creates no queue entry and never reports queued. Bound unconsumed scope entries per inbox at 256, preserving identical pending retry and control-command capacity. Keep private credentials and raw provider data out of queue and evidence.

Use the existing M06 account inbox, publication lock, ordinal allocator, digest and exact per-ID filename. A closed typed scope variant preserves exact bytes for all existing M06 control envelopes and terminal receipts. The mixed queue validates structural encoding, UUID and protocol. The scope publisher and compatible reader also verify the grant and envelope seal. A scope request is a proposal only. The M06 drain skips every structurally valid scope variant before its normal receipt and mutation paths. An invalid scope seal has no authority and cannot block unrelated control processing. ## Explicit and adopted commands

Reuse the bounded pinned owner-config parser, canonical UUID from the file, and the existing `Scope` and development binding types. M11 derives that reference from the queued command UUID using the trusted source authority. A typed Handoff uses the current project for the grant, validates the registered destination separately and carries exact before-generation and optional retained checkout. Reject unmatched action or unknown fields before publishing. Exact successful JSON remains `{"command_id": "<uuid>", "status": "queued"}`; sanitized refusal contains no queued acknowledgement. The scope producer returns queued or unavailable. The existing generic M06 status route remains separate.
