# #105 design · Verify canonical PR evidence

Build a read-only closure-owner verifier for an ordinary same-repository PR. It runs from the delivered target checkout and accepts a repository, PR number and declared target. Use the [accepted #103 design](../../103/design/github-ci-quality-gates-design.md), [ordinary PR binding amendment](../../104/design/github-tested-merge-binding-replan.md) and [signed probe](../../104/attachments/github-signing-probe-result.md). The live CI1 delivery must supply the authentic production artifact shape before JIT.

The input is the live GitHub PR and target, GitHub Actions workflow, newest exact canonical run and its latest attempt, authenticated jobs, current temporary merge and signed candidate v2 evidence. A successful check on an older run cannot mask current failure or ambiguity. Require ordered merge parents and an independently verified signed certificate with exact source, signer, configuration, event/ref, repository ID and invocation. Verify the attempt archive digest, safe bounded members, exact signed subject and current-attempt start times. Treat candidate contents as lane evidence and compare its identities and coverage claims against the trusted inputs. Record reviewed changes to gate-defining controls before eligibility.

Use authenticated read-only GitHub API access, pinned GitHub CLI attestation verification and a trusted verification environment. No repository, issue or branch mutation in the verifier. Report an explicit blocked disposition for missing, stale, malformed, insufficient or contradictory evidence, with enough evidence to identify the next action. Retain the unrounded 90% executable-helper line floor and use behavioral tests with independently constructed inputs and real valid signatures or isolated test PKI.

First prove the verifier's own source PR using the manually verified CI1 route. After protected delivery, run the trusted verifier on the handed-off documentation-only proof PR within the named proof scope described by the parent plan. Record separate, explicit owner authority for the retarget, fresh head push and unmerged closure, and for the signing permissions and public attestation publication, before Develop. That live proof and independent source review are this leaf's own delivery gates.
