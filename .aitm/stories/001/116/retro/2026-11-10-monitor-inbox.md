# #116 monitor inbox and registry regressions retrospective

**My scope** I implemented the monitor control inbox and CLI handlers and wrote the registry regressions for the capture rework. The inbox validates private owner configuration, publishes typed versioned commands in durable submission order, and uses a stable request UUID and canonical digest to distinguish exact retries from conflicting reuse. Its publication lock is separate from the coordinator lease. Status prefers committed outcomes and rereads the receipt if retirement races with a lookup. The CLI reports sanitized status and the command UUID.

**What worked** Fault injection reproduced a queue entry becoming visible after rename while directory sync failed. The exact retry now syncs the directory before reporting the existing entry. The inbox tests also exercised concurrent retries, process interruption after durable application and before queue retirement, and refusal to retire changed bytes. I reproduced the capture review findings on their held source before the fixes. My final focused run passed 326 tests across the registry, inbox, legacy, scanner, and provider suites. It covered fixed fences across writer restarts, moved transcripts before and after arming, callback omission, and Claude history across delayed re-enable.

**What I missed** My first frontier tests required each enrolled stream to produce another native observation before a disable could apply. That expectation left an idle stream able to stall the entire edge. I then tested removal from the approved installation without covering an archive move inside it, where the inode and stream key survive but the enrolled locator changes. My earlier Claude fixtures put the unfinished request at the tail, leaving out an abandoned partial followed by completed work. I also added the last delayed-enable assertions after the full local gate had started. The integration owner reran the gate on the frozen tree. [First source hold](../plan/source-review-attempt-1.md) · [Liveness hold](../plan/source-review-attempt-2.md) · [Moved locator and Claude history hold](../plan/source-review-attempt-3.md) · [Delivery checklist](../plan/delivery-checklist.md)

**Lessons** Exercise capture changes with no new provider event and distinguish a missing callback from verified absence or relocation. Put completed work after an abandoned request in provider fixtures and assert the original span dispositions through both disable and re-enable. Freeze the tests before handing off the exact gate so the evidence identifies the final tree.
