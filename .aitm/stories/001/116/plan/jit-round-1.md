Reuse the platform ACL, pinned-directory, identity and guarded lease primitives in `host_fs.py` and `ledger.py`. Use an account-private monitor root outside checkout, separate from individual project stores. All mutable registry and applied command receipts use a single durable transaction under one account coordinator lease. Expose that lease for the later journal and coordinator to reuse. Validate root ownership, physical identity, private mode and pinned path at every read/write, including recovery. Read-only status never creates state. No production service, migration or capture starts here.

`Registry.register_project(ProjectRegistrationRequest) -> RegisteredProject` uses an immutable project UUID and pinned private project state identity. Multiple physically distinct anchors can identify the same project. Resolve physical identity and ancestry before accepting owner-supplied anchors. The service consumes the registry view and performs discovery once per approved installation. Keep raw configuration paths private and out of CLI output, public receipts and export.

## Capture epoch and command contract

`Registry.set_permission(CaptureChange, VerifiedBoundary) -> CaptureEpoch` applies one native stream boundary to one project/source edge under the coordinator. Persist monotonically ordered, service-keyed boundaries, generation and permission state for each stream. The coordinator applies a source-wide command atomically to its known stream boundaries and keeps it queued while required proof is unavailable. New streams enroll only after a verified starting boundary while permission is enabled. Exact boundary retries preserve one decision and stale or contradictory boundary input fails closed. CLI JSON cannot supply proof. Existing M04 native references remain source evidence, and later scope resolution retains its own authority.

Evaluate eligibility from the original native span, not arrival or replay time. Use half-open permission intervals. A span wholly in an admitted epoch remains eligible for settlement from already-staged authorized evidence even if its revision arrives after disable. An unsplittable span crossing an enable or disable fence is a gap. A span in a disabled interval stays excluded after re-enable. Match stable source identity and native stream on every read. A revoked or no-longer-pinned root yields no new reads to repair a revision, even when already-staged authorized proof can settle. Later scheduler and routing owners call this registry seam.

`ControlInbox.enqueue(ControlCommand) -> ControlReceipt` uses a stable UUID and versioned typed, canonical owner-authorized envelope. Use private immutable atomic publication for queued bytes and exact readback on retry. Reusing a UUID for different payload is a conflict. Concurrent exact retries converge to one receipt, and submission can never claim application. The single monitor writer validates, applies and records the outcome in the same registry transaction. A crash after durable application and before queue cleanup replays without duplicate effects. Bootstrap uses the same command contract and coordinator lease. Path inputs are never copied to status output.

Extend `cli.py` with `monitor project register --config FILE`, `monitor source approve --config FILE`, `monitor project anchor add --project UUID --config FILE`, `monitor capture enable|disable --project UUID --source ID`, and `monitor command status --id ID`. Preserve existing global legacy state-directory versus monitor UUID parsing. Use explicit private config for owner declarations and stable caller-provided request IDs where supplied. For capture commands allow an optional request ID to retry across process boundaries and return the chosen stable ID. Use sanitized queued/applied/rejected status and a distinct unavailable command result. Tests exercise actual CLI parsing and queue persistence as well as direct registry operations. The startup service, runtime application loop and production adoption stay with their accepted later leaves.
