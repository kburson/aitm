## Typed wake and scheduling

- WakeHint carries exact MonitorProvider, verified keyed stream and session SourceRef values, optional verified turn SourceRef, optional verified project SourceRef, a scheduler-local integer generation, and a validated change or stop disposition. The generation increments only when the approved resolver produces a fresh service-keyed scheduling fact for that key. The value is local to wake scheduling, never a native cursor, provider ordinal or physical offset. A wire message supplies no generation or trusted hint. An unchanged keyed evidence reference is a duplicate. Coalesce by provider, session and verified turn, and retain the authenticated stream identity. An older frontier is a no-op. A later native append can reopen parked work at the same turn.
- Scheduler.notify(hint) retains the newest allowed hint under the current scheduler writer. Scheduler.take_due(now, limit) reserves monotonic work units without erasing pending state. The exact WorkItem carries a keyed hint, snapshot of its frontier and a process-local lease/token. Scheduler.finish(item, caught_up) retires only an exact current reservation with successful catch-up. A failed scan or expired process-local lease keeps its hint retryable. A stale completion never consumes newer work. Use an injectable positive lease TTL with a default of 5.0 monotonic seconds. Scheduler.notify finishes the pinned scopes._publish barrier before marking a hint due. If publication refuses, keep the previously committed scheduling state and create no in-memory-only due work. A link left by a directory-fsync failure must pass a pinned readback and fsync before restart can treat it as durable. Persist only canonical sealed keyed state, current disposition, the service-keyed scheduling fact and scheduler-local generation. Put files in a pinned private wake subdirectory under the approved user monitor root and reuse scopes._private_child, _read_private and _publish. No raw path, provider session string, turn ID, advisory text or cursor is persisted.
- Use Active, Settling and Parked. Validated stop or explicit keyed session park puts eligible current work into Settling and requires one final verified catch-up. A stop for a turn older than the currently known turn cannot park newer work. Keep independent concurrent turns due when appropriate. An explicit park settles every currently known turn for that exact keyed session. Newly admitted work can move the session back to Active. A verified later append reopens Parked immediately and bypasses the prior quiet/backoff deadline. A failed scan retains the exact durable hint and retries with monotonic backoff between 0.25 and 8 seconds. Restart discards in-flight capabilities and treats retained pending hints as due at the new monotonic origin. Keep resume/cursor recovery with #121. Preserve old native cursors through all scheduler and park paths.
- Limit selection to the requested positive bounded limit. Round-robin due groups by verified project ref, with unscoped streams independently keyed. Within a group take one due stream per round before taking its next. Retain the next group across calls so with G eligible due groups, each group is served within G consecutive take_due(now, 1) calls. A group whose work was marked capacity-held is deferred out of the current due set, so it cannot consume another group's next turn. A full project produces failed/unfinished work for scheduler purposes and leaves another due project eligible. The isolated coordinator fixture exercises #119's hold and exact acknowledgment boundaries.

## Same-account endpoint and generic launcher

- Bind an AF_UNIX stream endpoint named wake.sock within monitor_registry.default_monitor_root(), which derives the private user location from the current account, independent of provider-supplied paths. Refuse when the absolute filesystem-encoded address is longer than 103 bytes excluding the terminator. Hold the existing private root pin and the coordinator lease for bind, intake and cleanup. Bind with the exact absolute path, compare absolute lstat to dir_fd lstat without symlink traversal, require a private same-owner socket and use the measured Python os.chmod(name, 0o600, dir_fd=root.fd, follow_symlinks=False) on both hosts. Confirm the same inode again before listen. If the measured non-follow operation is unavailable, refuse without falling back to a link-following chmod. Cleanup only that unchanged inode. A preexisting unsafe or live socket refuses. Reclaim a same-owner 0600 socket from a stopped prior listener only under the coordinator lease, with an exact unchanged path proof and nonblocking ECONNREFUSED. Treat EAGAIN/EINPROGRESS and successful connect as live or saturated. None authorizes removal.
- Require the accepted connection's UID before payload parse. Use checked Darwin libc getpeereid and Linux libc getsockopt SOL_SOCKET/SO_PEERCRED. Pin argtypes, restype, returned credential size, successful return and nonnegative native values; fail closed on missing API or any error. Allocate one bounded connection read at a time. Accept one strict v1 JSON message terminated by LF then write-side EOF, at most 2,048 bytes including the LF and 30 ms of monotonic read time. The exact accepted bytes equal json.dumps(sort_keys=True, separators=(",", ":"), ensure_ascii=True) plus one LF. Require integer v=1 with bool refused. Reject repeated or unknown keys, NaN/Infinity, BOM, noncanonical escapes/spacing, trailing data, oversize, invalid UTF-8 or wrong UID. Locator must be a nonempty string, no NUL and at most 1,024 UTF-8 bytes, within the frame limit.
- A change/stop wire message has exactly v=1, kind change or stop, provider and a bounded native locator. WakeResolver.resolve(request, *, lease) returns one closed WakeResolution variant: resolved, unknown-locator, wrong-source-type, or stop-without-verified-current-turn. The lease is Registry.lease from monitor_registry.py, the held ledger._PinnedPath for the single coordinator. The resolved variant includes typed source and service-keyed scheduling facts only, with verified current-turn status for a stop. Actual provider locator proof goes through the existing _approved_candidate or Grok _grok_admission, via the explicitly bound #121 coordinator resolver. WakeIngress validates exact lease identity, closed outcome and service-key references, then the module-private issuer creates the scheduler's WakeHint and local generation. There is no public constructor accepting a frontier, and Scheduler.notify refuses a hint without the current issuer capability. Parsed or refused requests never reach notify. Park applies only to a known keyed session under the same lease. #120 tests the dormant interface with a current approved real-source fixture; #121 wires the real resolver and native source reads, and #320 retains native hook activation.
- The park wire form has exactly v=1, kind park and a service-keyed session selector and goes through the existing monitor parser as monitor park --session-ref REF. The active coordinator resolves the selector against known current scheduler entries. Park never writes scope, the approved profile, or a cursor.
